# RINGFALL のフィールドを作る

決めごとの正本は `docs/ringfall/field-design.md`。この手順はそれを作業の順に並べたもの。迷ったら正本を読む。

いちばん大事な方針（作り手の言葉のまま）：

> 同じような建物がたくさんあると特徴がない。同じ建物ばかりだと手抜きに見える。細かいのがたくさんあるより、大きめの一体となった構造物が、自然とその役割を出すのが一番いい。全てをそれで賄えるわけではないので、そういう場合は、遮蔽物にも同じオブジェクトばかり使わず、特徴を持たせたオブジェクトを使う。

## 1. 読む

- `docs/ringfall/field-design.md`（寸法の物差し、POI の型、構造物と遮蔽の決めごと、測り方、今の数字、作り直しの順番）
- `docs/ringfall/brief.md`（見た目の約束。見た目を変える前に必ず）
- 触る POI の関数（`map.ts` の `control()` など）と、`CLAUDE.md` のその POI の説明

## 2. 基準を取る

```bash
npm run look:ringfall -- <POI> --base     # 画像・field・variety の基準
npm run variety:ringfall -- <POI>         # 使い回している物・同じ形の構造物・ランドマーク
npm run field:ringfall -- <POI>           # 遮蔽と視線
```

`look` には Chromium が要る（`CHROMIUM_PATH` で指定できる）。

## 3. 役割を決めてから置く

1. その場所が「何の施設か」を一言で書く（例：発射を管制した耐爆の壕）。
2. その役割がそのまま形になる**大きな構造物を 2〜4 つ**決める。それぞれの形が、遮蔽・高所・通路のどれを兼ねるかも書く（例：壕の土盛り＝登れる高所、壕＝横から撃たれにくい通路）。
3. 構造物どうしは形を変える（低い土盛り、高い塔、皿、屋根のように、シルエットで見分けられるように）。同じ `building()` を並べない。
4. 足りない所だけ細かい遮蔽を置く。その場所の題材の物を使い、区画や方角ごとに変える。コンテナ・木箱・車止めの使い回しは避ける。足りない部品は、新しい関数（`cableDrum()` `deflector()` のような小さな関数）を作る。
5. 一番高い物を 1 つ決め、2 番目より目立って高くする（目安 +10 m）。

寸法は物差しどおりにする（跳んで越えられる高さ 2.9 m、よじ登れる高さ 6.2 m、ロボットが隠れる高さ 1.5 m、通路の幅など）。`tank()` の `h` は高さでなく上端の高さであるように、ヘルパーの引数の意味は定義を読んで確かめる。

## 4. 確かめる

```bash
npm run look:ringfall -- <POI>            # 基準と比べた field と variety、画像
npm run sim:ringfall -- 0                 # 配置の確認（点が箱の中にない、通れる）
npm run bench:ringfall -- 1               # sim を変えたので、前後で測る
```

- variety：struct 70% 以上、top 15% 以下、generic 25% 以下、twins 0（並べる意味がある時だけ）、landmark の差 +10 m 以上を目安にする。外れたら、なぜ外れてよいかを PR に書く。
- field：exposed は 30% 以下を目安にする。
- 画像：上空 4 枚と地上のカメラを Read で見る。**数字が良くても、画像で役割が読めなければ直す。** 遠くから見て何の施設か分かるか、同じ形が並んで見えないか、細かい物が散らかって見えないかを見る。
- 箱の上下が逆（`h <= y0`）になっていないかを確かめる。

## 5. 残す

- `docs/ringfall/field-design.md`：その POI の節（何を置いたか、前後の field と variety）、作り直しの順番の表、今の数字の表を更新する。
- `docs/ringfall/balance.md`：bench の前後の数字。
- `CLAUDE.md`：その POI の説明が変わったら書き直す。
- PR には前後の画像と数字の表を載せる。
