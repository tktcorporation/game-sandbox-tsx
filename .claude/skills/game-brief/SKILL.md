# game-brief

ゲームの質は、実装より前に決まる。誰がどんな不満を抱えて遊ぶのか、何を気持ちいいと感じるのか、どんな見た目を避けるのか。この 3 つが曖昧なまま作ると、どこかで見た平均的なゲームになる。このスキルは依頼をブリーフに固め、決めた完成条件を満たすまで作り込む。

## 1. ブリーフの材料を揃える

依頼に次の 4 つが揃っているか確かめる。欠けているものだけを、選択肢を添えてまとめて 1 回で聞く。

| 項目 | 例 |
| --- | --- |
| 遊ぶ人と、その人の不満 | FPS は好きだが対人戦が下手で楽しめない |
| 雰囲気（形容詞 3 つ） | 爽快 / 手触りがいい / 刺激的 |
| 避けたい体験 | 目的が分からない |
| 視点・形式 | 2D 見下ろし、3D 一人称など |

今のゲームを置き換えるのか、並べて追加するのかも確認する。置き換えるなら、消す範囲をユーザーに言い切ってもらってから消す。

## 2. 調べてから決める

作る前に、同じジャンルで評価の高いゲームの手触りを調べ、要点を抜き出す。調べた結果は、数値に落とせる指定に変える（例：撃破時のヒットストップ 45ms、最後の 1 体で 0.25 倍速を 350ms）。

## 3. `docs/brief.md` を書く

今の `docs/brief.md` と同じ節立てで書く。

- 誰のための何か
- 目的：画面を見て 3 秒で分かる勝ち方
- 雰囲気（3 語）
- 苦手な人でも気持ちいい仕組み
- 手触りの指定（数値）
- 見た目の方向：使う色は 4 色程度に絞る
- 使わないもの

「使わないもの」には、AI が作ると出がちな定番の見た目を名指しで並べる。今のリストを引き継ぎ、スクリーンショットを見て新しく見つけた癖を足していく。

ブリーフを書いたらユーザーに見せ、方向が合っているか確かめてから実装に入る。

## 4. 作りの約束

- ルールは `src/sim/` に置き、描画から切り離した決定的なシミュレーションにする。固定 tick の `step(state, input)` で進め、乱数の状態も state に持つ
- 調整用の数値は `src/sim/config.ts` に集める
- 描画側は `state.events` を受けて演出するだけで、ルールを変えない
- `window.render_game_to_text()` と `window.advanceTime(ms)` を公開し、自動で遊べるようにする
- 依存は `CLAUDE.md` の「Dependencies」に従う

## 5. 完成の判定

次の 4 つを満たすまで完成と言わない。

1. `npm run build` が通る
2. `npm run sim` で、腕前の違う複数のボットが全体を遊び切る。異常値・詰み・時間切れで失敗し、ランクやクリア時間が腕前ごとに分かれる。狙いの分布と最新の結果は `docs/balance.md` に書く
3. `npm run shots` で実際のビルドを最後まで遊び、コンソールエラーが無い
4. 保存されたスクリーンショットを自分で開いて見る。「使わないもの」に当たる見た目が無いか、狙った雰囲気が出ているかを確かめ、見つけた癖はリストに足して直す

最初は 1 画面だけを作ってスクリーンショットを見せる。方向が合ってから広げる。

## 6. 報告

人が遊ばないと分からないこと（手触り、音、スマホ実機での操作）は、確かめていないと明記して渡す。
