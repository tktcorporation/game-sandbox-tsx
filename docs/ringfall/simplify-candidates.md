### プレイヤーから見た変化（案 1・採用後）

- 野営に **依頼板** のラベル・使うが出ない（板の見た目は残ってよい）
- **今日の作戦** に「依頼」行がない（攻める拠点・装備）
- 次の一手が依頼板を指さない。拠点を持つまで **核 · 制圧** を前線に寄せる
- リザルトに済んだ依頼／契約の節が出ない（板オフ時）
- 強度付きの契約・物語の記録を板から選ぶ導線がない

### 資源・進行

- 保存データの `quests` / `board` / `taken` はそのまま。版の繰り上げなし
- 板オフ時は依頼報酬・契約報酬を精算しない（`offered()` が空、`takenContract` が null）
- 入門依頼のクレジット等は出ない。代替のスタート金の増額はしない（前線制圧・箱・拠点収入に寄せる）
- 月次の島の解放・工場・作業場は依頼に依存しない

### 復活手順

1. `src/ringfall/meta/features.ts` の `FEATURES.questBoard` を `true` にする  
2. ローカル確認: 野営で依頼板のラベル → 使う → 入門／今日／物語が出る。次の一手・今日の作戦に依頼行が戻る  
3. 任意: ブラウザコンソールで `window.ringfallFeatures.questBoard = true`（リロードなしの試し）  
4. shots の依頼板まわりはフラグを一時的に `true` にして既にカバーしている（復活後もそのままでよい）  
5. 文言・glossary の依頼語は SoT に残してあるので、板を戻すだけで足りる

## 0c. 決定（2026-11-24）— 島の出来事を外す（PR1/3）

| 項目 | 内容 |
| --- | --- |
| **採用** | **島の出来事**（破片の落下・嵐・回収部隊の来訪）をプレイヤーから外す |
| **理由** | コアの「出撃 → 前線を押す → 持ち帰る → 拠点を育てる」一本線に対して、初日から「明日 破片の落下」などの予告が野営地・地図・出撃の情報ノイズになっていた |
| **やり方** | コードは削除しない。`FEATURES.islandEvents = false`（`src/ringfall/meta/features.ts`）で無効化。復活可 |
| **やらない** | 出来事ロジックの削除、プロフィール版の繰り上げ |

### プレイヤーから見た変化（オフ時）

- 野営の地図の机に「今日／明日」の出来事行が出ない。机の印に「明日 嵐」などが付かない
- 今日の作戦・出撃画面・レイド中の目的カード・リザルトに「島の出来事」が出ない
- レイドで破片の箱・嵐の視界・回収部隊が来ない（日送りでも抽選しない）

### 資源・進行

- 保存データの `events` はそのまま読める。版の繰り上げなし
- オフ時は `eventFor` / `advanceDay` / `newRun` が静かな日として扱い、古い予告も適用しない（`eventsShown`）
- 地域レイド表・ベンチは出来事に依存しない想定。島キャンペーンは出来事日がなくなる分、嵐／回収部隊の日の戦況が変わりうる（balance.md の「島の出来事は 30 日のうち 12 日」行はフラグオン時の記録）

### 復活手順

1. `src/ringfall/meta/features.ts` の `FEATURES.islandEvents` を `true` にする  
2. ローカル確認: 地図の机に今日／明日、印に「明日 …」、出来事日のレイドで箱／嵐／回収部隊  
3. 任意: ブラウザコンソールで `window.ringfallFeatures.islandEvents = true`（リロードなしの試し）  
4. shots の出来事パートはフラグを一時的に `true` にしてカバーしている

## 1. 体験目的（遊びの芯）・一文

**出撃で前線を押し資源を持ち帰り、拠点を育てて島を解放する——対人は同じ線の非同期の攻めと守り。**

月次の勝ちは島の解放。作業場・工場・倉庫は手段。ランキング（トロフィー）は副次。出典: design-direction「いまの主ゴール」、multiplayer-experience 案 A。

## 2. 要素の棚卸しと評価

評価の軸は体験目的に対して:

| 印 | 意味 |
| --- | --- |
| **芯** | 線の真ん中に効く。残す／ sharpen |
| **重複** | 同じ一手が別入口・別語で並ぶ |
| **分かりづらい** | 初見で次の一手を濁す／語が衝突する |
| **ほぼ使われない** | 序盤に触れない／後半専用。隠す候補 |

### 2.1 野営の設備

| 要素 | プレイヤーから見た一手 | 評価 | メモ |
| --- | --- | --- | --- |
| 車両 | 出撃画面を開く | **芯** | 出撃の主入口 |
| 門 | 門を出てレイド開始 | **重複** | 車両と同じ「出撃」だが確認なしで即レイド |
| 今日の作戦 | 攻める拠点・依頼・装備の一行 | **芯** | 次の一手の骨格。依頼行が板と二重 |
| 地図の机 | 島の地図・来る遠征・トロフィー・明日の出来事 | **芯／重複** | 守り確認は芯。出撃地図と見た目が近い |
| 依頼板 | 入門／今日の依頼／物語の依頼 | **外した（§0）** | フラグオフ。流れを分けていた |
| 倉庫の棚 | 中身・持っていく物・倉庫のレベル | **芯** | 持ち帰りと次の出撃の結節 |
| 商人の屋台 | 買う／売る | **芯** | 資源→装備。倉庫一覧が左に再掲 |
| 作業場 | 医務室・作業台・倉庫・無線機・ポーチ・道 | **芯／重複** | 育てる手段。倉庫カードが棚と二重 |
| 工場 | 自軍の部隊をレベルを上げる | **芯** | CoC 型の自軍。Lv0〜8 は情報量が多い |
| 信号所 | お隣・トロフィー・島の知らせ | **分かりづらい／ほぼ使われない（序盤）** | 1 日目は鍵だらけ・サーバー未接続。遠征 0/1 の意味が薄い |

### 2.2 レイド中

| 要素 | 評価 | メモ |
| --- | --- | --- |
| 核 · 制圧／固める | **芯** | 前線と守りの一手 |
| 中継ボックス（倉庫へ送る／切り上げて生還） | **芯** | 持ち帰りの一手 |
| 補給箱・保管庫・鍵 | **芯** | 資源。保管庫は中盤以降 |
| 脱出 | **芯** | 生還。種類が多いが覚える必須ではない |
| 目標カード・コンパス | **芯** | 次の一手 |
| 来る遠征（地図・今日の作戦） | **芯** | 守りの入口。頻度は約 5 日に 1 度＋初回 |
| 短いレイド／攻める（お隣の前線） | **芯（対人層）** | 語が前線・攻める・短いレイドで三重に聞こえやすい |
| 強度 | **分かりづらい／ほぼ使われない（序盤）** | 契約を受けてから。初見の板を埋める |
| 改造パーツ・解析 | **ほぼ使われない（序盤）** | 核報酬・高強度帯 |
| 島の出来事（破片の落下／嵐／回収部隊） | **外した（§0c）** | フラグオフ。1 日目から「明日 破片の落下」が出ていた |

## 3. sim・通し確認の裏付け（数字）

出典はいずれも [balance.md](balance.md)「現在の結果」／island campaign／hideout pacing／ai islands。通し確認は野営 1 日目。

| 事実 | 簡素化への効き |
| --- | --- |
| ダム湖 生還 60% / 50% / 77%（初心者・普通は目標未満） | 初回は前線一つ＋生還に寄せ、箱漁り・別依頼で伸ばさない方が学習しやすい |
| 港湾 中央値 ~2 分・掃討 0・船出し | 「出撃一回＝同じ濃さ」が崩れる。短い地域は目標の短縮版が要る（または後半） |
| 発射場 生還 17% / 47% / 47% | 序盤に出さない／入口を遅らせる候補 |
| 30 日解放 22 / 23 / 21 日目 | 月次弧は届く。ゴール表示を sharpen する価値あり |
| 拠点 day5: casual n1、beginner n4 | 序盤の前線体験が薄い日がある |
| ai islands 来訪 7–8 / 30 日（約 5 日に 1 度＋初回） | 来る遠征・信号所は毎日の主役にしない。序盤は隠してよい |
| hideout：全設備最上段 40 / 24 / 21 レイド中央値 | 設備を全部最初から見せると「箱集め」に読まれる |
| 倉庫抱え込み想定で Lv 上げ直後に溢れ 0（stash-cap） | 倉庫レベル自体は芯。入口の二重が問題 |
| 通し: 1 日目の信号所はお隣すべて鍵・「島のサーバーにつながっていません」 | 触れても次の一手にならない |
| 通し: 依頼板に入門 3＋今日 4＋物語が並び、今日の作戦の前線と制圧が重なる | 次の一手が割れる |
| 通し: 倉庫のレベルが倉庫の棚と作業場の両方 | 重複 |

## 4. 優先度順の案（候補）

実装量: **S** 文言・表示のみ、**M** パネル／依頼の組み替え＋軽いルール、**L** システムの組み替え。  
保存移行: プロフィール版の繰り上げが要るか。

### 案 1 — 依頼板を外す（**採用・方針変更済み**）

当初案は「前線を一つ」中心に削るだった。ユーザー判定で **依頼板ごと無効化**（§0）。

| 項目 | 内容 |
| --- | --- |
| 扱い | **隠す（機能フラグ）／復活可** |
| プレイヤーから見て何が変わるか | §0 参照。線は出撃→前線→持ち帰り→拠点だけ |
| 失うもの | 入門／今日／物語の依頼とその報酬・強度レバー・板からの記録目標 |
| 実装量 | **M**（`FEATURES.questBoard`、野営ラベル／次の一手／今日の作戦／精算） |
| 保存移行 | **不要** |
| sim | 地域レイド表・ベンチハッシュは依頼に依存しない想定。hideout pacing は依頼納品をしない分、進みが遅くなる可能性 |
| 文言 | 【元】依頼板で入門・今日の依頼・物語を選ぶ 【案】依頼板を出さない（フラグオフ） 【理由】体験目的に対して流れを分けていた。後から `questBoard: true` で復活可 |

### 案 2 — 倉庫のレベル入口を倉庫の棚だけにする

| 項目 | 内容 |
| --- | --- |
| 扱い | **まとめる** |
| プレイヤーから見て何が変わるか | 作業場から倉庫カードが消える。倉庫を上げるのは倉庫の棚だけ。作業場は医務室・作業台・無線機・ポーチ（と道） |
| 失うもの | 作業場から倉庫を上げる近道 |
| 実装量 | **S–M**（作業場のカード非表示。倉庫.md の「作業場にも従来どおり」を改訂） |
| 保存移行 | **不要** |
| sim | 枠の数字は不変。ゲートハッシュ不変想定 |
| 文言 | 【元】作業場にも倉庫カードがある 【案】倉庫のレベルは倉庫の棚だけ 【理由】枠数が見える場所に一手を寄せる（warehouse 既存方針の完了） |

### 案 3 — 信号所・トロフィー・お隣を「対人が始まるまで」隠す

| 項目 | 内容 |
| --- | --- |
| 扱い | **隠す（後半に回す）** |
| プレイヤーから見て何が変わるか | 来る遠征が立つ／お隣の前線が開く／最初の他プレイヤー陣地が出るまで、野営に信号所ラベルを出さない（または近づいても「まだ先」）。トロフィーは地図の机からも序盤は出さない。島の知らせは対人結果が付いてから |
| 失うもの | 初日に海の向こうの島を眺める体験。トロフィー初期値の可視化 |
| 実装量 | **M**（表示ゲート。ルールは既存のまま） |
| 保存移行 | **不要** |
| sim | ai islands 来訪は 7–8/30。隠しても戦闘表は動かない |
| 文言 | 【元】信号所が最初からあり、トロフィー 1000・鍵付きお隣が出る 【案】対人の一手が立つまで信号所を出さない 【理由】触れても次が無い設備を線の外に退ける |

### 案 4 — 強度・改造パーツを序盤から出さない

| 項目 | 内容 |
| --- | --- |
| 扱い | **隠す（後半に回す）** |
| プレイヤーから見て何が変わるか | 今日の依頼を受けても強度ボタンは出ない（例: 拠点 N 個 or 解放周 or 入門完了後）。改造パーツの拾い・解析は同じ条件まで通知を抑えるか、解析 UI を出さない |
| 失うもの | 序盤の難易度ダイヤルとパーツ育成 |
| 実装量 | **S–M** |
| 保存移行 | **不要**（既存の強度・既知パーツはそのまま。UI だけ遅延） |
| sim | 強度 0 のままの表が序盤の正になる。契約報酬の脅威倍は後から |
| 文言 | 【元】契約に強度が並ぶ 【案】序盤の契約は通常のみ 【理由】覚えるレバーを後回しにする |

### 案 5 — 出撃入口を車両に一本化（門の即レイドをやめる）

| 項目 | 内容 |
| --- | --- |
| 扱い | **まとめる** |
| プレイヤーから見て何が変わるか | 門でも車両と同じ出撃画面（スタート・装備・目的の確認）を開く。確認なしで島に出ない |
| 失うもの | 門からすぐ歩き出る手触り |
| 実装量 | **S–M** |
| 保存移行 | **不要** |
| sim | 不変（ボットは門の即出を使わない） |
| 文言 | 【元】車両か門から出撃（門は確認なし） 【案】門も車両と同じ出撃画面 【理由】出撃のプライマリ入口を一つに |

### 案 6 — 地図の机を「今日の守り」に寄せ、普段の島眺めは出撃地図へ

| 項目 | 内容 |
| --- | --- |
| 扱い | **まとめる／ sharpen** |
| プレイヤーから見て何が変わるか | 来る遠征が無い日、地図の机は短く「守りなし・明日の出来事」か、次の一手で車両を優先。来る遠征がある日だけ机を最優先（game-design-review 提案 D）。島全体の色とスタート選びは出撃画面の地図が主 |
| 失うもの | 野営でいつでも同じ密度の島地図を眺める習慣 |
| 実装量 | **S–M**（tip 優先とパネルの情報量） |
| 保存移行 | **不要** |
| sim | 不変 |
| 文言 | 【元】地図の机＝常時の島地図 【案】来る遠征の日は「今日の守り」、平時は出撃地図が主 【理由】設備のプライマリを一つに（design-direction 原則 5） |

## 5. 残すもの（削らない）

体験目的に効いているので、簡素化の対象外（手触りの芯）:

- 核の制圧／固める、中継ボックス、生還、工場、倉庫（容量そのもの）、クレジットと回収品、来る遠征、攻める／短いレイド（対人層・方針確定済み）、移動（スライド・ジップ・登り）、リオ

対人の入口語（攻める・来る遠征・短いレイド・トロフィー）は [multiplayer-experience.md](multiplayer-experience.md) / §5.8 で確定済み。**語の再発明はしない。** 簡素化は「いつ出すか」「入口をいくつ見せるか」に留める（案 3・4）。
