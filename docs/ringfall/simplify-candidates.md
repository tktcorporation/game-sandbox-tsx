### プレイヤーから見た変化（案 1・採用後）

- 野営に **依頼板** のラベル・使うが出ない（板の見た目は残ってよい）

- 次の一手が依頼板を指さない。拠点を持つまで **核 · 制圧** を前線に寄せる
- リザルトに済んだ依頼／契約の節が出ない

### 資源・進行

- 保存は v37：旧 `quests` / `board` / `taken` / `records`（v34）と `events`（v35）は読み飛ばして落とす。夜の襲撃・地図の机は Profile 専用フィールドなし（スタック整合のため v36→v37 に繰り上げ）
- 依頼報酬・契約報酬の精算コードはない。入門依頼のクレジット等も出ない
- 代替のスタート金の増額はしない（前線制圧・箱・拠点収入に寄せる）
- 島の育成・工場・作業場は依頼に依存しない（島の解放は 2026-11-25 に方向として外す）

### 復活手順

1. 削除直前のコミット（この PR の親）から依頼板まわりのコードを Git 履歴で戻す  
2. ローカル確認: 野営で依頼板のラベル → 使う → 入門／今日／物語が出る。次の一手・今日の作戦に依頼行が戻る  
3. 文言・glossary・shots の依頼板まわりも履歴側と揃える  

フラグや `window.ringfallFeatures` では復活しない。

## 1. 体験目的（遊びの芯）・一文

**出撃で前線を押し資源を持ち帰り、自分の島を終わりなく育てる——対人は同じ線の非同期の攻めと守り。**

長期の軸は島を終わりなく育て、外側の拠点を保ち、部隊戦へ力を出す。**島の解放は方向として外す（2026-11-25）。** 作業場・工場・倉庫・ポーチは手段。ランキング（トロフィー）は副次。出典: design-direction「島は終わりなく育てる」、multiplayer-experience 案 A。

## 2. 要素の棚卸しと評価

評価の軸は体験目的に対して:

| 印 | 意味 |
| --- | --- |
| **芯** | 線の真ん中に効く。残す／ sharpen |
| **重複** | 同じ一手が別入口・別語で並ぶ |
| **分かりづらい** | 初見で次の一手を濁す／語が衝突する |
| **ほぼ使われない** | 序盤に触れない／後半専用。隠す候補 |

| --- | --- |
| ダム湖 生還 60% / 50% / 77%（初心者・普通は目標未満） | 初回は前線一つ＋生還に寄せ、箱漁り・別依頼で伸ばさない方が学習しやすい |
| 港湾 中央値 ~2 分・掃討 0・船出し | 「出撃一回＝同じ濃さ」が崩れる。短い地域は目標の短縮版が要る（または後半） |
| 発射場 生還 17% / 47% / 47% | 序盤に出さない／入口を遅らせる候補 |
| 30 日解放 22 / 23 / 21 日目 | 月次弧は届く。ゴール表示を sharpen する価値あり |
| 拠点 day5: casual n1、beginner n4 | 序盤の前線体験が薄い日がある |
| ai islands 来訪 7–8 / 30 日（約 5 日に 1 度＋初回） | 来る遠征・信号所は毎日の主役にしない。序盤は隠してよい |
| hideout：全設備最上段 40 / 24 / 21 レイド中央値 | 設備を全部最初から見せると「箱集め」に読まれる |
| 倉庫抱え込み想定で Lv 上げ直後に溢れ 0（stash-cap） | 倉庫レベル自体は芯。入口の二重が問題 |
| 通し: 1 日目の信号所はお隣すべて鍵・「島のサーバーにつながっていません」 | 触れても次の一手にならない |
| 通し: 依頼板に入門 3＋今日 4＋物語が並び、今日の作戦の前線と制圧が重なる | 次の一手が割れる |
| 通し: 倉庫のレベルが倉庫の棚と作業場の両方 | 重複 |

## 4. 優先度順の案（候補）

実装量: **S** 文言・表示のみ、**M** パネル／依頼の組み替え＋軽いルール、**L** システムの組み替え。  
保存移行: プロフィール版の繰り上げが要るか。

### 案 1 — 依頼板を外す（**採用・方針変更済み・コード削除済み**）

当初案は「前線を一つ」中心に削るだった。ユーザー判定で **依頼板ごと外す**（§0）。2026-11-24 にコードごと削除。

| 項目 | 内容 |
| --- | --- |
| 扱い | **コード削除**。復活は Git 履歴から |
| プレイヤーから見て何が変わるか | §0 参照。線は出撃→前線→持ち帰り→拠点だけ |
| 失うもの | 入門／今日／物語の依頼とその報酬・板で選ぶ強度レバー・板からの記録目標 |
| 実装量 | **M**（野営ラベル／次の一手／今日の作戦／精算／`meta/quests|contracts|story` 削除） |
| 保存移行 | **v34**（旧 `quests` / `board` / `taken` / `records` を落とす） |
| sim | 地域レイド表・ベンチハッシュは依頼に依存しない想定。hideout pacing は依頼納品をしない分、進みが遅くなる可能性 |
| 文言 | 【元】依頼板で入門・今日の依頼・物語を選ぶ 【案】依頼板を出さない（コード削除） 【理由】体験目的に対して流れを分けていた。復活は削除直前のコミットから |

### 案 2 — 倉庫のレベル入口を倉庫の棚だけにする

| 文言 | 【元】作業場にも倉庫カードがある 【案】倉庫のレベルは倉庫の棚だけ 【理由】枠数が見える場所に一手を寄せる（warehouse 既存方針の完了） |

### 案 3 — 信号所・トロフィー・お隣を「対人が始まるまで」隠す

## 5. 残すもの（削らない）

体験目的に効いているので、簡素化の対象外（手触りの芯）:

- 核の制圧、中継ボックス、生還、工場、倉庫（容量そのもの）、クレジットと回収品、攻める／短いレイド（対人層・方針確定済み）、移動（スライド・ジップ・登り）、リオ、島の自動防衛と島の知らせ

対人の入口語（攻める・短いレイド・トロフィー）は [multiplayer-experience.md](multiplayer-experience.md) / §5.8 で確定済み。来る遠征の**予告 UI** は §0b で削除（自動防衛は残す）。**夜の襲撃は §0d で削除済み。核 · 固めるは §0g で削除済み。** **語の再発明はしない。** 簡素化は「いつ出すか」「入口をいくつ見せるか」に留める（案 3・4）。
