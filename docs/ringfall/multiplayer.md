# 他のプレイヤーとの遊び

各プレイヤーは自分の島を持つ。他のプレイヤーと関わる道は 1 つ、**攻め**（別プレイヤーの陣地へのレイド）だけ。同時に同じ場にいることは無く、結果だけがサーバーを通って相手に届く。言葉は [glossary.md](glossary.md) に従う。

遠征（工場の部隊を他の島へ送り、数で自動に解く仕組み）は 2026-11-28 に削除した。予告、貸し出し、呼び戻し、短いレイド（X2）もそれと一緒に無い。コードは Git の履歴から戻す。

## 1 日の流れの中で

1. **野営に入る**：留守の間に陣地が稼いだ分を受け取り、攻められた記録を見る（信号所）
2. **門から出る**：自分の島のレイドか、「攻める」一覧から別プレイヤーの陣地への攻めを選ぶ
3. **攻め**：相手の陣地 1 つだけが舞台。守るのは相手の工場の部隊と島の守り。核を制圧すれば取れる
4. **結果**：星（0〜3）でトロフィーが動き、制圧の報酬を受け取る
5. **相手の側**：次に開いたとき、だれに・どこを・星いくつで攻められたかと、その記録（動き）が見える。やり返せる

## 攻め

- **相手**：別プレイヤーが自分の島で持つ陣地。`meta/sortie.ts` の `sortieTargets()` が、ゲーム自身の島（AI の島）の陣地と、別プレイヤーの島が最後に見せた陣地を、トロフィーが近い順に並べる
- **舞台**：`newRun(..., { sortie })`（`sim/` の `State.sortie`、`SORTIE`）。その陣地の中継ボックスから始まり、時間切れ、離脱、中継ボックスのどれかで生きて終わる。詳しくは [holdings-raid.md](holdings-raid.md)
- **報告**：終わると攻めた側が結果を相手の島に送る（`POST /api/islands/:code/raids`）。制圧なら陣地はロボットに戻り、相手の記録に「取られた」と星とトロフィーが残る。制圧でなければ「守りきった」
- **守る側が失うもの**：陣地と、そこで稼いだ分だけ。置いていた島の守りは倉庫に戻る。物は取られない
- **攻めの記録**：攻めの間の動き（数秒ごとの位置と、核・撃破・終わりの印）を報告に付け、相手の信号所で再生できる（`sim/replay.ts`、新しい `ISLAND_RULES.replayMax` 件まで）

## 留守の間

サーバーの島は、要求が来たときだけ変わる。留守の間に島の上で戦いは起きない。

- **別プレイヤーの攻め**：上のとおり、相手が遊んだ結果だけが届く
- **AI の島の攻め**：ブラウザが、最後に見てからの時間でくじを引く（`meta/away-attacks.ts`）。1 UTC 日に失う陣地は `OUTER_GUARD.lossCap` まで
- **陣地の稼ぎ**：時計で貯まり、野営に入ったときに受け取る（`meta/income.ts`）

## 別プレイヤーの見つけ方

サーバーは、トロフィーが近い他のプレイヤーの島を最大 4 つ返す（`GET /api/neighbours`）。最近 2 週間に遊んだ島からトロフィーが近い順に 24 まで集め、週ごとに少し入れ替えて 4 つ選ぶ。答えはセーブに入れず、ブラウザに置く（`cachedNeighbours()`）。島の番号を知っていれば、信号所からその島を見ることもできる（見るだけ）。

4 つに満たない分は、ゲーム自身が動かす島（AI の島、`meta/ai-islands.ts`）が埋める。サーバーが無くても同じ。

- 名前の横に必ず「AI」と出す。他のプレイヤーのふりはしない
- 顔ぶれはブラウザのプレイヤーの id から決まる。自動操作の下では毎回同じ
- プレイヤーの島の日に合わせて陣地を増やす
- ブラウザの中だけのもの。問い合わせは `island-net.ts` が手元で答え、サーバーには届かない
- `npx tsx scripts/ringfall-ai-islands.ts` が確かめる

## 守りの決まり

| 決まり | 内容 |
| --- | --- |
| 新しいプレイヤーの保護 | 島を取ってから `ISLAND_RULES.protectDays`（2 日）は攻めで陣地を取られない |
| その日の守り | 陣地を 1 つ取られたら、残りはその UTC 日の終わりまで取られない。1 日に失うのは `OUTER_GUARD.lossCap`（1）まで |
| 取れない場所 | 発着場（タイタン）は誰のものにもならない |
| 取った陣地 | 取った側のものにはならず、ロボットに戻る。`SORTIE_META.regrow` 日は攻め先に出ない |

`npx tsx scripts/ringfall-outer-guard.ts` と `scripts/ringfall-real-raids.ts` が確かめる。

## サーバー

| 部品 | 置くもの |
| --- | --- |
| Worker（`worker/index.ts`、`worker/api.ts`） | API の入口。プレイヤーの識別、相手探し、報告の受付 |
| Durable Object `IslandDO`（`worker/island-do.ts`） | 1 つの島の陣地の持ち主と、持ち主が読む記録。読み込み・適用・保存だけを持つ |
| `worker/island.ts` | 島の状態と、その書き換え（純粋な関数 `islandOp()`）。アラームも時計も持たない |
| D1 | プレイヤー、島の要約、島の番号と持ち主の対応、その週の相手 |

プレイヤーは、端末で作る匿名の ID と表示名で識別する。D1 と `ISLAND` の束縛のつなぎ方は [infrastructure.md](infrastructure.md) が正本。束縛が無い間、API は 202（`no-database` / `no-island-server`）を返し、遊びは変わらない。

島の番号は Crockford の base32 の 6 文字で、島を取るときにサーバーが引いて渡す（端末に決めさせると、持ち主より先に他の人が取れてしまう）。Worker は世界を組み立てず、拠点の並びは `map.ts` から書き出した表（`src/ringfall/meta/island-table.ts`）から読む。

| 要求 | 誰が | 中身 | 答え |
| --- | --- | --- | --- |
| `POST /api/islands` | 島を持つ人 | `{ player: { id, name } }` | 201 と島の番号 |
| `PUT /api/islands/:code` | 持ち主 | レイドの後の報告：`{ player, holds, retaken, factory, day, parcels?, takenParcels? }` | 200 と島の陣地の持ち主。違う ID は 403、取られていない番号は 404 |
| `GET /api/islands/:code` | 誰でも | | 200。持ち主の表示名、拠点の持ち主と攻められるか（`open`）、守りの残り、島の守り。プレイヤーの ID は含めない |
| `GET /api/islands/:code/log?after=<n>`（`Authorization: Bearer <id>`） | 持ち主 | | 200 と、番号 `n` より後の記録（取られた・守りきった・取り返した）。ヘッダーが無ければ 401、持ち主でなければ 403 |
| `POST /api/islands/:code/raids` | 攻めた人 | `{ from: { id, name, code }, target, captured, stars?, won?, replay? }` | 200 と `taken`。攻めた人は自分の島を ID で示す。相手に見える名前は、攻めた人の島が持つ名前 |
| `GET /api/neighbours`（`Authorization: Bearer <id>`） | 島を持つ人 | | 200 と最大 4 つの島 |

持ち主の報告は、攻めで取られた陣地を消せない。報告が自分の陣地としていても、`retaken`（そのレイドで取り返した拠点）に無ければロボットのままに残る。ブラウザの島は、取られたことを知る前の写しのままレイドに出ることがあるため。

遠征があった頃に保存された島は、読み込むときに遠征とその戦いの状態を捨て、遠征隊が持っていた拠点をロボットに戻す（`migrateIslandState()`）。`npx tsx scripts/ringfall-island-server.ts` が API と一緒に確かめる。

### 残っている名残

次のものはサーバーに残っているが、ブラウザはもう使っていないか、使い道が薄い。整理の候補。

- 海岸の拠点を別プレイヤーと共有する写し（`contestedMirror` / `contestedDefend`、`contested_holds`）
- 島の地図に残す印（`POST …/pings`）と、他の島に島の守りを置く口（`POST …/aid`）

## 不正への構え

レイドと攻めの結果はブラウザの申告を信じる。被害は 1 つの島の中に留まり、1 日の上限と保護がそれを抑える。シミュレーションは種と入力から同じ結果を出すので、後の段階で、申告された結果を Worker で再生して確かめられる。
