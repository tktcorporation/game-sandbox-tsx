# RINGFALL：他のプレイヤーの島へ攻め込む陣取り

各プレイヤーは自分の島を持ったまま、工場の部隊（遠征隊）を他のプレイヤーの島へ送る。遠征隊が相手の拠点を制圧すると、その拠点は相手の島の中で自分のものになり、自分の陣地として数える。プレイヤーどうしは撃ち合わない。戦うのはロボットどうしで、その持ち主がプレイヤーになる。

戦いは 2 つの場で起きる。島の持ち主が遊んでいない間は、サーバーが数で計算する。持ち主がレイドで遊んでいる間は、攻めてきた遠征隊が持ち主のレイドに現れ、近くではロボットとして動く。インフラは Cloudflare（Workers・Durable Objects・D1）で組む。

関連 Issue：#124

## 遊びの流れ

1. **遠征を出す**：キャンプの工場で、攻め込む相手の島と狙う拠点を選び、部隊を送る。部隊は相手の島に、敵と同じ上陸の手段（発着場へのドロップシップ、北岸への船）で降りる。
2. **攻められる**：自分の島に他のプレイヤーの遠征隊が来ると、キャンプの地図と翌日の予報に出る。レイド中に来た遠征隊は、上陸から自分の拠点の核へ歩く姿が見える。
3. **取られる・取り返す**：他のプレイヤーに取られた拠点は、自分のものでも敵のものでもない拠点になる。前線にあれば、敵の拠点と同じく核で制圧して取り返せる。自分の工場の部隊も、取り返しに向かう。

## 勢力と拠点の持ち主

陣取り戦（`src/ringfall/sim/battle.ts`）の勢力（`Side`）に、4 つ目として「他のプレイヤー」（`3`）を足す。他のプレイヤーの部隊は、持ち主のプレイヤーの ID を持つ。

| 勢力 | 部隊の出どころ | 拠点を取るか | 誰と戦うか |
| --- | --- | --- | --- |
| 自軍（0） | 自分の工場 | 取る | 敵・野良・他のプレイヤー |
| 敵（1） | 敵の拠点と上陸地点 | 取る | 自軍・野良・他のプレイヤー |
| 野良（2） | 野から | 取らない | すべて |
| 他のプレイヤー（3） | その人の工場から遠征で | 取る（狙った拠点だけ） | 自軍・敵・野良 |

拠点の持ち主（`NodeHold`、`src/ringfall/sim/holds.ts`）は、自分の（`freed`）、敵の（`held`）、他のプレイヤーの（`rival:` にプレイヤー ID を続けた文字列、`RivalHold`）の 3 通り。文字列にしたのは、持ち主の配列を `===` で比べ、そのまま写し、セーブに書けるようにするため。他のプレイヤーの拠点は自分のものではないので、前線の判定（`frontNodes()`）では敵の拠点と同じに扱い、核で制圧して取り返せる。敵の守備隊は立たない。夜の攻撃（`nightRaids()`）は他のプレイヤーの拠点には起きず、隣の拠点を数える「敵の地面」にも入れない。敵の強さ（`enemyNodes()`）は敵の拠点だけを数え、他のプレイヤーの拠点はどちらの側にも数えない。セーブ（`Profile.v` 26 以降）は他のプレイヤーの拠点をそのまま持ち、v25 以前のセーブに書かれていても敵の拠点として読む。v27 は出している遠征、記録の読んだ番号、報告待ちの取り返した拠点を持ち、v26 以前のセーブはどれも無し（番号 0）として読む。

遠征隊（`RivalExpedition`：持ち主、狙う拠点、部隊、出発の時刻）は `newRun(..., { battle: { factory, rivals } })` で陣取り戦に渡す。発着場か北岸のうち、狙う拠点まで歩く道のりが短いほうに降り（`rivalRoute()`）、途中の拠点の持ち主にかかわらず歩き抜け（通り抜ける拠点では、守備隊との戦いにも制圧にも加わらず、守りに来いという知らせも出さない。ただし途中で `CONQUEST.meet` の内に出会った部隊とは戦い、その拠点に立つ工場の砲台とも撃ち合う）、狙った拠点を取って守る。持ち主の ID が `parseHold()` で読めない遠征隊（空・空白入り・65 文字以上）は渡しても来ない。持ち主がすでに持つ拠点へ時刻 0 で送られた遠征隊は、初めからそこに立って守る。

## 陣地の数え方

自分の陣地は、自分の島で持つ拠点と、遠征で他の島に持つ拠点の合計になる。

| 数 | 増えると何が起きるか |
| --- | --- |
| 自分の島の拠点（今の綱引きの帯） | 今と同じ（開くもの、出撃地点、収入） |
| 遠征で持つ拠点 | 1 つにつき 1 日の収入（`FRONT.income`）が増える。綱引きの帯とは別に数を出す |

遠征で持つ拠点の収入は、レイドの精算（`settle()`）で、遠征の最後に見た状態が保持中のものを数えて払う（`awayIncome()`、`Settlement.awayIncome`）。リザルトでは拠点の収入とは別の行に出る。

## 工場の遠征

キャンプの工場のパネルの下に、遠征の欄（`src/ringfall/view/expeditions.ts`）を置く。欄は自分の島の番号とそのコピー、出している遠征とその状態、相手の島へ遠征を送る入力からなる。送る手順は、相手の島の番号を入れて見る、遠征を受ける拠点（公開の状態の `open`）から 1 つ選ぶ、送る、の 3 つ。送る部隊は、サーバーが自分の島に持つ工場の段（公開の状態の `factory`、最後の報告の段）の部隊（`FACTORY.levels[].kinds`）で、送る直前に読み直す。キャンプで工場を上げても、サーバーに届くのは次のレイドの後の報告なので、それまでは前の段の部隊が出て、欄に一行そう出る。出せる遠征の数は工場が一度に出す部隊の数（段の `max` と、持つ拠点が足す部隊）まで。サーバーが断った理由は、エラーの符号ごとの一文（`src/ringfall/meta/island-errors.ts` の `ERROR_TEXT`）で出す。Worker の拒否はこの一覧の型で書くので、一覧に無い符号は返らない。

サーバーにつながらない間（202 の `no-island-server`、つながらない、ブラウザの自動操作の下）は、欄に「島のサーバーにつながっていません」の一行だけを出し、ほかの遊びは変わらない。要求はブラウザだけのモジュール（`src/ringfall/island-net.ts`）にまとめ、答えの読み取りと島への取り込みは純粋な関数（`src/ringfall/meta/expeditions.ts`）にする。

| いつ | 何をするか |
| --- | --- |
| レイドの精算の後 | 島の番号が無ければ取り（`POST /api/islands`）、持ち主の報告を取り返した拠点（`retaken`）とともに送り、記録の続きと島の公開の状態を読む。答えを待たずに遊びは続く |
| 工場のパネルを開いたとき | 島の番号が無ければ取って報告する。あれば報告は送らず（報告は守備隊を満たし直すため）、記録と公開の状態を読む。出している遠征の相手の島を読み直し、状態を更新する |

サーバーの拠点の持ち主は、他のプレイヤーの拠点についてだけ島に取り込む（`mergeHolds()`）。次のレイドの最中（精算したレイドのリザルトの間は含まない）に届いた答えは、報告が届いた送り待ちを外すだけで、持ち主と記録は取り込まない（次の同期が読み直す）。後から始まった同期がすでに取り込まれた答え（レイドの後とパネルの開き方のどちらも）も、報告が届いた送り待ちを外すだけにする。後の同期が捨てられたり失敗したりしたときは、前の答えをそのまま取り込む。工場のパネルを閉じると、その開き方への答えは捨てる。サーバーが他のプレイヤーのものとする拠点はその人のものに、島が他のプレイヤーのものとしていてサーバーがそうしない拠点はサーバーの持ち主にする。自分の拠点と敵の拠点は島のままにする。自分が核で取り返した拠点は、次の報告でサーバーに届く。

記録の新しい項目（遠征が来た、拠点を取られた、遠征隊を全滅させた、取り返した、手放されて敵に戻った）は一度だけ知らせる。キャンプでは地図の机の「島の知らせ」に並び、机の印に件数が出る。精算の後の同期がリザルトの表示中に届けば、リザルトにも出る。読んだ番号は `Profile.logSeq` に持つ。

出している遠征（`Profile.expeditions`：相手の島の番号、狙う拠点、送った時刻、相手の島での番号、部隊の人数、状態）は、相手の島の公開の状態で、自分の島の番号と狙う拠点が一致する遠征の状態（来る途中・攻撃中・保持中）をとる。読めた公開の状態に無ければ、全滅したか拠点を失ったものとして「戻らない」にし、次の精算で外す。

送った遠征は、答えを待たずに「送っている」として島に入り、その間も部隊を 1 つ割く（その間に始めたレイドも割いた数で戦う）。答えが番号を返せば向かっている遠征になり、断られるかつながらなければ取り除く。パネルを閉じても答えは島に取り込む。答えの来ないまま 1 分（`SENDING_MS`）を過ぎた「送っている」遠征は、次に工場のパネルを開いたときと読み込んだときに取り除く。送る間の 2 つの要求（自分の島の公開の状態と遠征）は、それぞれ 20 秒（`SEND_TIMEOUT_MS`）で諦めてつながらなかったものとし、取り除くので、まだ答えを待っている遠征が 1 分で取り除かれることはない。相手の島の公開の状態で遠征の状態を更新するのは、状態を読みに行った時点でサーバーの番号があった遠征だけで、その後に番号が付いた遠征は、古い状態に無くても戻らないとしない。

**遠征の費用**：まだ戻らない遠征は、1 つにつき自分の島の陣取り戦で工場が一度に出す部隊を 1 つ減らす（`newRun(..., { battle: { factory, away } })`、`factoryMax()` から引いて 0 未満にはしない）。欄には島の守りに残る部隊と遠征中の部隊の数を並べる。遠征を出していない間、陣取り戦は変わらない。

## 戦いの解き方

島ごとに 1 つの Durable Object（`IslandDO`）を置き、その島の拠点の持ち主と、来ている遠征隊を持たせる。島の状態を書き換えるのはこの 1 か所だけにして、順番の食い違いを防ぐ。

**遊んでいない間**：`IslandDO` は決まった間隔（アラーム）で、来ている遠征隊と島の守り（守備隊と、持ち主の工場の部隊）を数で戦わせる。数での戦いは、陣取り戦が遠くの部隊に使う計算（`CONQUEST.tick` ごとの戦いと制圧）と同じ式にする。その式は `src/ringfall/sim/reckon.ts` の純粋な関数で、Worker とブラウザの両方で同じコードを動かす。レイドは戦い（`reckonFights()`）と制圧（`reckonCaptures()`）の間に、核のそばに立つロボットを世界から渡す。誰も遊んでいない島は、その両方を数だけで続ける `reckonApart()` で解く。部隊の歩み（`march()`）は道のりの形（`walkLine()` の線）を読むので、まだ `battle.ts` に残る。Worker で動かすには、リンクごとの道のりの長さを表にして渡す形に切り出す。

**レイド中**：持ち主がレイドを始めると、`IslandDO` は来ている遠征隊をレイドに渡し、その間は自分では解かない（貸し出し）。遠征隊は他のプレイヤーの勢力の部隊として陣取り戦に入り、プレイヤーの近く（`CONQUEST.near` の内）ではロボットとして動く。レイドが終わると、ブラウザが結果（拠点の持ち主と、残った遠征隊）を `IslandDO` へ返す。返らないまま貸し出しの期限が過ぎたら、`IslandDO` は貸し出す前の状態から数で解き直す。

## サーバー

| 部品 | 置くもの |
| --- | --- |
| Worker（`worker/index.ts`） | API の入口。プレイヤーの識別、相手探し、遠征の受付 |
| Durable Object `IslandDO`（島の Worker `ringfall-islands`、`islands/`） | 1 つの島の拠点の持ち主、来ている遠征隊、貸し出し |
| D1 | プレイヤー（ID・表示名）、島の要約（持つ拠点・工場の段・強さ）、遠征と戦いの記録 |

プレイヤーは、端末で作る匿名の ID と表示名で識別する。アカウントへのひも付けは後の段階で足す。

### データベースのつなぎ方

API（`worker/api.ts`）は D1 を `DB` という名前の束縛で読む。束縛が無い間、`/api/island` は 202（`no-database`）を返し、ブラウザはその答えを捨てるので、遊びは変わらない。つなぐ手順は次の 4 つ。

1. データベースを作る：`npx wrangler d1 create ringfall`。出力の `database_id` を控える。
2. 手元の `wrangler.jsonc` に束縛を足す（まだ push しない）：`"d1_databases": [{ "binding": "DB", "database_name": "ringfall", "database_id": "<控えた id>" }]`。`wrangler d1 migrations apply` は、設定に載っているデータベースにしか表を作れない。
3. 表を作る：`npx wrangler d1 migrations apply ringfall --remote`。表の定義は `migrations/` にある。
4. 束縛を足した `wrangler.jsonc` を push する。

この順に進める。存在しないデータベースへの束縛を push すると Workers Builds のデプロイが失敗し、表の無いデータベースへの束縛では書き込みがすべて 503（`db-error`）になる。

### 島の番号と遠征の API

相手探しの仕組みができるまで、攻め込む相手は島の番号で選ぶ。島の番号は、Crockford の base32（I・L・O・U を除く英数字）6 文字で（`src/ringfall/meta/island-code.ts`）、プレイヤーが島を取るときにサーバーが乱数で引いて渡す（`POST /api/islands`）。端末が選べる番号や、端末で計算できる番号は、持ち主より先に他の人が取れてしまうため、番号は端末に決めさせない。引いた番号がすでに誰かの島なら引き直し、`CLAIM_TRIES`（8）回続けて塞がっていたら 503（`no-free-code`）を返す。番号は人に教えてよい公開の名前で、島の持ち主であることは秘密の ID で示す。端末は渡された番号を匿名の ID と一緒に保存する（`meta/identity.ts` の `rememberCode()`）。

島ごとの Durable Object `IslandDO`（`worker/island-do.ts`）は `ISLAND.idFromName(番号)` で引く。状態の書き換えは純粋な関数（`worker/island.ts`）にまとめ、`IslandDO` は読み込み・適用・保存とアラームだけを持つ。Worker は世界を組み立てない（`map.ts` の読み込みは数秒かかる）。拠点の並び・段・守備隊は、`map.ts` から書き出した表（`src/ringfall/meta/island-table.ts`）から読む。表と `map.ts` の食い違いは `scripts/ringfall-expeditions.ts` が検出し、`--write` で書き直す。

| 要求 | 誰が | 中身 | 答え |
| --- | --- | --- | --- |
| `POST /api/islands` | 島を持つ人 | `{ player: { id, name } }` | 201 と、サーバーが引いた島の番号。島は取った時点で、すべての拠点が敵のもの |
| `PUT /api/islands/:code` | 持ち主 | レイドの後の報告：`{ player: { id, name }, holds, retaken, factory, day }`。`holds` は `NODES` の順の拠点の持ち主、`retaken` はそのレイドで取り返した拠点の ID（重複なし、拠点の数まで。省くと空） | 島を取った ID なら 200 と島の拠点の持ち主、違う ID は 403、取られていない番号は 404（報告では島を取れない） |
| `GET /api/islands/:code` | 誰でも | 持ち主の表示名、拠点の持ち主と遠征を受けるかどうか、来ている遠征（送った島の番号と名前、狙う拠点、残る部隊の数、来る途中・攻撃中・保持中） | 200。プレイヤーの ID は含めない |
| `GET /api/islands/:code/log?after=<n>`（`Authorization: Bearer <id>`） | 持ち主 | 番号 `n` より後の変化（遠征の到着、拠点を取られた、遠征を全滅させた、取り返した、保持していた部隊が尽きて敵に戻った）と次の番号。秘密の ID は URL に載せず、ヘッダーで渡す | 200。ヘッダーが無ければ 401、持ち主でなければ 403 |
| `POST /api/islands/:code/expeditions` | 攻める人 | `{ from: { id, name, code }, target, units }` | 201 と遠征の番号。送る人は自分の島を ID で示し、部隊の数は自分の工場の段の部隊（`FACTORY.levels[].kinds`）の人数まで。他の人に見える名前は、要求の `name` ではなく送る人の島が持つ名前 |

束縛 `ISLAND` が無い間、`/api/islands/` への正しい要求は 202（`no-island-server`）を返す。本文の上限と読み方は `/api/island` と同じ。

持ち主の報告は、サーバーが他のプレイヤーに渡した拠点を消せない。消せるのは、報告が `retaken` に挙げ、かつ自分の拠点とした拠点だけで、その拠点の遠征隊は去り、記録に残る。`retaken` に無い拠点は、報告が自分の拠点としていても他のプレイヤーのものに残る。ブラウザの島は、取られたことを知る前の写しのままレイドに出ることがあるため。ブラウザの取り返した拠点は、レイドの精算（`settle()`）が、レイドを始めたときの島（`State.hold`）から決める。レイドで核を制圧した拠点と、レイドの始まりに他のプレイヤーのものだった拠点のうちレイドの後に自分のものになった拠点で（`retakenNodes()`）、送り待ちとして `Profile.retaken` に足す。報告はそのたびに送り待ちをすべて `retaken` に挙げ、200 の答えが返ったものだけを送り待ちから外す。報告が届かなかった拠点は次の報告でまた挙がり、その間の同期は、サーバーがまだ他のプレイヤーのものとしていても、送り待ちの拠点を自分のものに残す。報告が届かない間に、送り待ちの拠点を別のプレイヤーがあらためて取ると、遅れて届いた報告がその制圧も取り消す。送り待ちが続くのは報告が届かない間だけなので、この食い違いは受け入れている。報告のたびに、守備隊は満ちた状態から戦い直す。

**遊んでいない間の解き方**：遠征隊は受け付けから一定の時間（`EXPEDITION.arrive`）で狙った拠点に立つ。リンクの道のりはまだ表にしていないので、上陸と行軍を 1 つの時間にまとめる。拠点に立った後は、島の時計を `CONQUEST.tick` 秒ずつ進め、レイドと同じ `reckonApart()` で戦いと制圧を解く。守る側は、敵の拠点ではその拠点の守備隊（段の板金は島の番号とロボットから決める）、持ち主の拠点では工場の砲台（`FACTORY.levels[].turrets`）と、工場が `every` 秒ごとに `max` 部隊まで送る部隊（`kinds`）になる。工場は持ち主が遊んでいない間も働いていたものとして、最初の部隊は遠征隊の到着と同時に立つ。乱数は使わず、同じ状態と同じ時刻からは同じ島になる。何も起きない間（来る途中の遠征と、拠点を保持するだけの遠征と、その日の上限で控えている遠征しかない間）は、時計を次の出来事の手前まで飛ばす。アラームは、戦いが続く間は 1 分ごと、来る途中の遠征か控えている遠征しかなければその到着か次の日（UTC）の始まりに鳴り、拠点を保持するだけの遠征しかない島では鳴らない。島の状態は、刻みを解いたときと要求が島を変えたときだけ保存し、読むだけの要求では書かない。

| 決まり（`EXPEDITION`） | 値 | 理由 |
| --- | --- | --- |
| `protectDays` | 2 日 | 島を取ってから 2 日は遠征を受けない（新しいプレイヤーの保護） |
| `perIsland` | 3 | 1 つの島に同時に来る遠征。拠点を保持している遠征も数え、取られたままの拠点が増え続けないようにする |
| `perDay` | 2 | 1 日（UTC）に遠征に取られる拠点の数。その日の分を取られた後は、新しい遠征を受けず、着いている遠征隊は次の日まで戦いにも制圧にも加わらず、工場の部隊もそこへ向かわない。次の日、その拠点の戦いは到着したときと同じく始まる（砲台が立つ）。取られた数は記録とは別に数える |
| `arrive` | 134 秒（`CONQUEST.land.ship` と 120 秒） | 上陸から狙う拠点までの歩きをまとめた時間 |
| `alarmMs` | 60 秒 | 戦いが続く島を解く間隔 |
| `maxTicks` | 3600 | 1 回に解く刻みの上限。遅れている島はすぐに続きを解く |

遠征を受けない拠点は、発着場（タイタン）、キャンプに隣り合う拠点、他のプレイヤーが持つ拠点、すでに遠征が向かっている拠点。自分の島へは送れない。

### 島の Worker のつなぎ方

`IslandDO` は、ゲームの Worker とは別の Worker `ringfall-islands`（`islands/wrangler.jsonc`、入口は `islands/index.ts`）に置く。Durable Object を実装する Worker には Cloudflare のプレビュー URL が作られず、適用していないマイグレーションがあるとバージョンの upload も通らないため、ゲームの Worker には実装を置かない。ゲームの Worker は `script_name` で島の Worker の `IslandDO` に束縛する。束縛 `ISLAND` は `DB` と同じく任意で、無い間 `/api/islands` は 202（`no-island-server`）を返す。つなぐ手順は次の 2 つ。

1. 島の Worker を一度デプロイする：`npx wrangler deploy -c islands/wrangler.jsonc`。Workers Builds で回すなら、ルートの設定を `islands/wrangler.jsonc`、デプロイのコマンドを `npx wrangler deploy -c islands/wrangler.jsonc` にした 2 つ目のプロジェクトを作る。
2. ルートの `wrangler.jsonc` に `"durable_objects": { "bindings": [{ "name": "ISLAND", "class_name": "IslandDO", "script_name": "ringfall-islands" }] }` を足して push する。

この順に進める。まだ無い Worker への束縛を push すると、ゲームの Worker のデプロイが失敗する。

## 不正への構え

最初の段階では、レイドの結果はブラウザの申告を信じる。シミュレーションは種と入力から同じ結果を出すので、後の段階で、申告された結果を Worker でレイドを再生して確かめられる。島どうしの影響は遠征の数で上限を決めておき、1 人の不正が他の島へ及ぶ範囲を限る。島を取る要求（`POST /api/islands`）にはまだ回数の制限が無く、相手探しと通知の段階で足す。

## 守りの決まり

- **新しいプレイヤーの保護**：始めて数日の島には遠征が来ない。
- **来る遠征の上限**：1 つの島に同時に来る遠征隊の数と、1 日に取られる拠点の数に上限を置く。
- **取れない拠点**：発着場（タイタン）と、キャンプに隣り合う拠点は遠征で取れない。島から締め出されることが無いようにするため。

## 段階

それぞれを 1 つの Issue と PR にする。

1. **4 つ目の勢力**：勢力と拠点の持ち主に「他のプレイヤー」を足し、数での戦いの式を純粋な関数に切り出す。サーバーはまだ無く、ゲートが作り物の遠征隊で、取る・取られる・取り返すを確かめる（`scripts/ringfall-rivals.ts`）。他のプレイヤーどうしは 1 つの勢力として数え、持ち主の違う遠征隊どうしは戦わない。そのため、この段階では B の遠征隊は A が持つ拠点を取れない（守る側も攻める側も同じ勢力 3 に数えられ、守りがいる扱いになる）。
2. **サーバーの土台**：匿名の ID、D1 の表、レイドの後に島の要約を送る API。遊びは変わらない。
3. **遠征と、遊んでいない間の戦い**：工場から遠征を出す画面、`IslandDO` とそのアラームでの解決、取られた拠点の表示。
4. **レイド中の遠征隊**：貸し出しと、レイドの陣取り戦への遠征隊の参加、結果の返却。
5. **相手探しと通知**：強さの近い相手を選ぶ仕組み、保護と上限、攻められたことの知らせ。

## 決めたこと

- **島**：今のセーブ（`Profile`）の島のまま加わる。拠点の持ち主はサーバーの写し（`IslandDO`）を正とし、ブラウザはレイドの前に読み、後に書き戻す。
- **遠征の費用**：遠征隊は工場の部隊から割く。送った分だけ、自分の島の陣取り戦に出る部隊が減るので、攻めるか守るかを選ぶことになる。
- **取った拠点の維持**：他の島に持つ拠点は、工場の部隊を守りに置き続けて保つ。守りの部隊が尽きる、または割り当てを外すと手放し、その拠点は相手の島で敵の拠点に戻る。遊ばなくなった人の島が取られたままにならず、取った側も持てる数が工場の大きさで決まる。
