# RINGFALL の画面の決めごと

HUD、野営地の板、出撃画面、地図、結果画面（`src/ringfall/style.css`、`view/hud.ts`、`view/hub.ts`、`view/map.ts` ほか）を、先に決めた枠の中で作るための決めごと。モデルの決めごと（[models.md](models.md)）と同じく、色・字の大きさ・押せる大きさを先に決め、検査がそれを測る。

検査は 2 つある。

| 検査 | 何を読むか | いつ走るか |
| --- | --- | --- |
| `npm run lint:ringfall`（`scripts/ringfall-ui-lint.ts`） | スタイルシートと画面のコード | `npm run build` の中（ゲート 1）。数秒 |
| 画面の計測（`scripts/ringfall-ui-audit.mjs`） | 実際に描かれたページ | `npm run shots:ringfall` がスクリーンショットを撮るたび（ゲート 3） |

画面を足すか変えたら、`npm run lint:ringfall` を通し、変えた画面を撮るパートを `npm run shots:ringfall -- --part <名前>` で回して、計測の結果とスクリーンショットを見てから出す。

決めごとを足すときは、この文書に理由を書き、同じ変更で検査に足す。検査の無い決めごとは守られない。

## コードから読める決めごと（lint）

### 色は意味の名前で `view/palette.ts` から取る

画面の色は `view/palette.ts` の `UI` にだけ書く。1 つの色は 1 つの意味を持ち、同じ意味のものはどの画面でも同じ色になる（敵の土地は地図でも帯でも凡例でも `foe`）。

- スタイルシートでは `var(--foe)`、透かすときは `rgb(var(--foe-rgb) / 0.5)` と書く。`:root` の一覧は `npm run lint:ringfall -- --write` が `palette.ts` から書き出す。手で直さない
- コードでは `UI.foe`、透かすときは `alpha(UI.foe, 0.5)` と書く
- 新しい色が要るときは、意味を 1 行書いて `UI` に足してから使う。似た色がすでにあるなら、それを使う

`#ff5a4f` のような色をスタイルシートやコードに直に書くと、lint は失敗する。この決めごとを入れる前は、敵を表す赤だけで 20 種類ほどが画面ごとに少しずつ違っていた。

世界の色（地面、建物、ロボット）は `models.ts` の `PAL` にあり、`npm run models:ringfall` が見る。

### 字の大きさは段から選ぶ

字の大きさは 11・12・13・14・16・18・20・24・30・40・54 px のどれかにする（タイトルの `clamp()` と、親に合わせる `em` は別）。11 px 未満は使わない。スマホで読めない。

段の間の大きさ（15 px、17 px）が要ると感じたら、隣の段で足りないかを先に確かめる。1 px 違いの字が並ぶと、どれが見出しでどれが本文かが読み取れなくなる。

### 字の太さと書体

読み込んでいる太さは、M PLUS 1p の 500 と 800、Saira Condensed の 600 と 800 だけ（`ringfall/index.html`）。`font-weight` はこの 3 つから選ぶ。ほかの値は、ブラウザが近い太さで代用するか、輪郭を太らせて描く。

書体は `var(--num)`（数字と短いラベル）か `var(--jp)`（文）で指定する。等幅フォントは使わない（brief の「使わないもの」）。

### 角と重なり

角の丸みは 0（板とカード）、2〜3 px（キーの印）、6 px（小さな札）、50%（丸いボタン）のどれか。`z-index` は 1〜10 に収める。

### 見た目はスタイルシートに書く

`ringfall/index.html` に `style` 属性を書かない。コードから字の大きさを決めない（クラスを付けて、スタイルシートで決める）。値が動くもの（ゲージの幅、物ごとの色）は、`--w` や `--c` のような変数をコードから渡す。

## 描いてから測る決めごと（画面の計測）

撮影のゲートは、スクリーンショットを撮る直前に、そのページを測る。測るのは次の 8 つ。

| 名前 | 見つけるもの | 基準 |
| --- | --- | --- |
| clip | 自分の枠か、囲む枠に切られた文字 | 省略記号（…）で切るものと、端をぼかす枠（方位の帯）は除く |
| offscreen | 画面の端からはみ出した文字 | スクロールできる枠の中は除く |
| ghost | 上に載った半透明の板から透けて見える文字 | 上の板の濃さが 0.15〜0.97 |
| overlap | 重なって描かれた 2 つの文字 | 小さい方の 25% 以上が重なる |
| small | 小さすぎる文字 | 11 px 未満 |
| contrast | 地の色と近すぎる文字 | WCAG の比で 4.5 未満（18 px 以上か、14 px 以上の太字は 3 未満）。板が透けて見える先は昼の砂の色として測る |
| bare | 板も影も無いまま世界の上に置かれた文字 | 板の濃さが 0.4 未満で、`text-shadow` も無い |
| tap | スマホで、押すものが小さすぎる | 短い辺が 40 px 未満 |

数は `scripts/ringfall-ui-audit.mjs` の `RULES` にある。

### 分かっている違反は一覧に置き、減らす一方にする

`scripts/ringfall-ui-baseline.json` は、今ある違反の一覧（画面ごとに、決めごとの名前と要素）。計測は一覧と比べて、

- 一覧に無い違反が出たら、ゲートは失敗する。新しく作った画面や、変えた画面が決めごとを破ったということ
- 一覧にある違反が消えていたら、一覧を書き直すように言う。`UI_AUDIT=write npm run shots:ringfall` が書き直す

一覧は減らす一方で、増やさない。新しい違反を一覧に足して通すのは、決めごとの方が間違っているときだけで、そのときはこの文書の基準を直す。

計測の結果は `shots/ringfall/ui-audit/` に、パートごとの JSON で残る。

## 見て確かめること

検査が測れるのは、切れ・重なり・大きさ・色の近さまで。次は人が（またはスキル `ringfall-ui-review` で）スクリーンショットを見て確かめる。

- 数字や印が、今の仕組みの何を測っているか
- 名前と数だけで伝わるか。説明の文に頼っていないか（brief の「使わないもの」）
- 画面を閉じたとき、次にすることが分かるか
