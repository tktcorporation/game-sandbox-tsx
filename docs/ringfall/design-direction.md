# RINGFALL 設計方針

この文書は、RINGFALL の体験をどう組み立てるかの判断基準である。機能仕様（brief・island・multiplayer）や画面の細部（ui・ux-design）より先に読む。迷ったときはここへ戻る。

関連: [ux-design.md](ux-design.md)（体験の線と場所のプライマリ）、[glossary.md](glossary.md)（プレイヤー向け用語の正本）、[multiplayer-experience.md](multiplayer-experience.md)（マルチ体験の一本化）、[game-design-review.md](game-design-review.md)（楽しさ・進行・動機の点検・実装前）、[simplify-candidates.md](simplify-candidates.md)（簡素化の候補と決定・依頼板／反応型守り／島の出来事／夜の襲撃削除）、[raid-loot.md](raid-loot.md)（他プレイヤー拠点の制圧戦利品）、[warehouse.md](warehouse.md)（倉庫のレベル）、[brief.md](brief.md)、[ui.md](ui.md)、[multiplayer.md](multiplayer.md)、[island-v2.md](island-v2.md)。

**簡素化の決定（要約・2026-11-24）:** 外した機能はコードごと削除する（`FEATURES` フラグは使わない）。復活は Git 履歴（削除直前のコミット）から。依頼板（入門・今日の依頼・物語）、反応型の対人守り（来る遠征の予告→核で固めるの迎撃 UI）、島の出来事（破片の落下・嵐・回収部隊）、**夜の襲撃**（今夜の狙い・日をまたいでの拠点喪失）、**地図の机**は削除済み（前スタック PR1〜4）。**出撃の入口は門だけ**（車両の出撃導線・設備は削除）。**核 · 固める**（来る遠征向けの非同期閉門）も削除済み（§0g）。出撃・島眺めは **門**、トロフィー・島の知らせ・島の守りは **信号所**。詳細は [simplify-candidates.md](simplify-candidates.md) §0／§0b／§0c／§0d／§0e／§0f／§0g、[pvp-clarity.md](pvp-clarity.md)。

**お隣は自分の島の前線に立つ（方向 A・2026-11-25／TKT-195）:** 海に面した 4 拠点をお隣と取り合い、普段のレイドでその核を制圧することが攻めになる。短いレイド・「○○の前線」・出ている遠征・遠征に出すはコードごと削除（スタック PR6）。詳細は下の「お隣は前線に立つ」と [multiplayer-experience.md](multiplayer-experience.md)、[multiplayer.md](multiplayer.md)。

用語の約束: プレイヤーが画面で見ない内部名（depot / pad / parcel など）を、UI・PR・報告・この文書のプレイヤー向け説明に使わない。荷物を送る場所は brief どおり **中継ボックス**。画面に出す語は [`src/ringfall/view/copy.ts`](../src/ringfall/view/copy.ts) と [glossary.md](glossary.md) を正とする（`npm run lint:ringfall-copy`）。

## 何を目指すか（参考の「意味」）

参考はスーパーセル（特にクラッシュ・オブ・クラン）のゲームデザインである。  
「クラッシュ・オブ・クラン風」とだけ書いて終わらせず、会話で拾った次の意味を RINGFALL の方針とする。

| スーパーセル側で効いていること | RINGFALL でそれが意味すること |
| --- | --- |
| 自分の村が主役 | **基本は自分の場所（拠点・野営・工場）に対して何かをする。拠点を育てるのが主役。** 島でのレイドは、その育成のための出撃である。 |
| 対人は守りと攻めに分かれ、非同期 | **他プレイヤーと直接リアルタイムで撃ち合うことはほとんどない。** 守りは自動（留守中に解決、結果は後から島の知らせで見る）。攻めだけ能動。クラッシュ・オブ・クランズの攻守と同じ型（[pvp-clarity.md](pvp-clarity.md)）。 |
| マルチは日常プレイの中に溶ける | **マルチは別モードでも特別な操作でもない。** 出撃・持ち帰り・拠点の育ちの線の中に、自然と入ってくる。 |
| 最初は全部わからなくてよい | **一目で全部理解できなくてもよい。** ただし、いまやってほしい次の一手は画面上で明確で、触っていくうちに仕組みが分かっていく。 |

RINGFALL は一人称の PvE レイドを持つが、長期の軸は「島の前線を押し、拠点を強くする」ことであり、他プレイヤーとのリアルタイム対戦ではない。

## いまの主ゴール（CoC 型・確定）

クラッシュ・オブ・クランズ的な体験を進める。**メインは自分の島を強くすること。** 島の解放を通じて自軍をパワーアップし、その過程で資源が要るので集めて強化し、解放が進み、他プレイヤーとも戦う。ランキングのような競争層は副次。

### 体験のループ（一文）

```
資源を集める → 自軍（工場・作業場・ロボット）を強くする → 島の解放が進む → 他プレイヤーと戦う
```

出撃の線（変わらない）はこのループの「資源を集める／前線を押す」の手段:

```
出撃 → 島で前線を押す → 持ち帰る → 拠点が育つ
```

| 層 | 何か | 画面の語 |
| --- | --- | --- |
| **月次の勝ち** | **島の解放**（拠点を押し、決戦まで） | 島・前線・核・制圧・解放 |
| **手段（育てる）** | **作業場**と**工場**（自軍のロボット・設備） | 作業場・工場・レベルを上げる |
| **日次の対人** | **攻めは門からの出撃一つ**（自分の島の前線に立つお隣の拠点の核 · 制圧）。**守りは自動**（工場の部隊＋島の守り） | 攻める・前線・島の知らせ |
| **副次の競争** | **ランキング＝トロフィー**（お隣の組み合わせにも使う） | 拠点を取ると増え、守りきると少し増え、取られると減る |

だからこうする／こうしない:

| こうする | こうしない |
| --- | --- |
| 今月の一文ゴールは「島の解放」 | 作業場の完成と島の解放を同格の「今月の勝ち」に並記する |
| 作業場／工場は解放と対人のための手段として見せる | 箱集めだけがゴールに見える |
| 他プレイヤーとの攻めは **普段の出撃** で前線の拠点を制圧するだけ。守りは自動。入口は出撃一つ | 短いレイド・「○○の前線」の別入口、来る遠征の予告→固める、信号所の遠征ボタン、写し全体 |
| ランキングはトロフィー（拠点の奪い合い）で、島を強くした結果の副次層。お隣はトロフィーが近い人 | ランキング専用モードや別ロビーを主軸にする |

**ランキング＝トロフィー（確定）:** 取り合う拠点を取ると増え、守りきると少し増え、取られると減る（二重計上なし）。お隣の組み合わせはトロフィーが近い順（拠点数の週次ペアリングは置き換え）。常時表示（HUD 左上・地図のお隣）。詳細は下の「トロフィーと物資」。  
**攻め＝自分の島の前線（確定・方向 A）:** 海に面した 4 拠点をお隣と取り合う。門から普段のレイドでその核を制圧することが攻め。短いレイド（旧 X2）と「○○の前線」は削除。信号所ボタンは置かない。詳細は下の「お隣は前線に立つ」。  
**率いる遠征（段階 6）は廃止のまま** — 写し全体・信号所出撃は戻さない。

### お隣は前線に立つ（方向 A・2026-11-25／TKT-195）

クラッシュ・オブ・クランへ寄せるための**暫定の一歩**。迷ったら CoC 側を選ぶ。

| CoC で効いていること | RINGFALL（方向 A）でそれが意味すること |
| --- | --- |
| 攻撃が資源・進行の主な入り口 | **攻める＝前線を押す。** 取った拠点は「拠点 あと N」を減らし、島の守りが倉庫へ届く |
| 自分の村が他人の攻め先 | **育てた工場の部隊と島の守りが、お隣から見た守備隊になる** |
| 防衛ログ | 起動時の一枚と信号所の島の知らせ（「{誰}が{拠点}を攻めた · 守りきった」など） |
| トロフィーで相手選び | **トロフィーが近い人がお隣** |
| シールド | **取られた拠点はその日のうちは取られない** |
| 勝ち＝トロフィー、資源庫＝物資 | **拠点の持ち主が変わるとトロフィー。核 · 制圧の手応えは物資（倉庫へ）** |

一文の一日:

```
門 → 出撃地図（お隣の拠点も普通の拠点）→ 自分の島のレイドで核 · 制圧 → リザルト（あと N → 島の知らせ → トロフィー内訳）
```

決まり（画面に出さない設計名は使わない。拠点はいつもどおりの名前＋持ち主）:

1. **取り合う拠点** — 海に面した 4 つ（観測所・浄水場・ロボット工場・追跡レーダー）。各お隣の組と 1 対で、持ち主は一人。
2. **攻め** — 門からの普段のレイドでその核を制圧すること。別の入口・別の舞台は無い。
3. **あと N** — 取り合う拠点も数える。取らなくても 16 には届く（取り合いの外の拠点だけで足りる）。
4. **守り** — 相手の拠点を守るのは持ち主の工場の部隊＋島の守り。
5. **トロフィー** — 取り合う拠点を取った／守りきった／取られたで動く。お隣の組み合わせにも使う。常時見える。
6. **その日の守り** — 取られた拠点はその日のうちは取られない。
7. **消すもの** — 短いレイド、「○○の前線」、出ている遠征、遠征に出す。遠征の拠点の収入は拠点の収入に一本化。

信号所は島の知らせ・トロフィー・お隣カード・島の番号（折りたたみ）だけ。攻めの入口ではない。トロフィーは信号所だけでなく、普段の HUD 左上と地図のお隣の名前の横にも出す。

先の姿（まだ実装しない）: リーグ、島ごとの盾の長さ、防衛ログの専用画面、攻撃回数の上限。方向 A はその手前で「攻める＝前線」「育てる＝守り」を一本にするための仮置き。

### トロフィーと物資（CoC の勝ち／資源庫・2026-11-25）

ユーザーの声: トロフィーがどこにあるかわからない。攻めたときと守ったときで増減してほしい。核を取ったときは物資多め、トロフィーを取ったときはトロフィーが増えるバランス。確認済み: **同じ攻めで、拠点を取ったらトロフィー、核を制圧したら物資多め**。迷ったらクラクラ寄り。

| CoC | RINGFALL |
| --- | --- |
| 攻撃勝利 → トロフィー増 | **取り合う拠点が自分のものになる** → トロフィー増（`TROPHY.base` 30 ± 差で最大 20） |
| 防衛勝利 → トロフィー少し増 | **お隣の攻めを守りきった**（島の知らせ「… · 守りきった」とセット）→ `TROPHY.defend` 10 |
| 拠点を取られる → トロフィー減 | **取り合う拠点を取られる** → トロフィー減（攻めと同じ幅） |
| 資源庫から資源 | **核 · 制圧** → その拠点の島の守りが倉庫へ。空でも `SEIZE.emptyReserve`、加えて `SEIZE.bonus`（AI の拠点も含む） |
| トロフィーはホーム画面左上 | **HUD 左上に常時。** 地図ではお隣の名前の横にも相手のトロフィー |

コード上「拠点を取る」と「核を制圧」は同じ操作（核のメーター）だが、精算では分ける:

- **トロフィー** — 相手持ちの**取り合う拠点**が自分のものになったときだけ（所有の変化）。
- **物資の上乗せ** — 核を制圧したとき（`seizeRivalLoot`。AI 含む。クラクラは NPC 村からも資源が取れるため）。

攻め側が守りきれなかったとき（0 星相当）のトロフィー減は**採らない**。RINGFALL の攻めは短い専用レイドではなく普段の出撃の核 · 制圧なので、「取れなかった＝増えない」を負けとする。防衛側の `defend` だけ足す。

数値の正本は `src/ringfall/meta/trophies.ts`（`TROPHY` / `SEIZE`）。リザルト・起動時カード・島の知らせのトロフィー行は攻め／守りの内訳が分かる形（`trophyLine`: 取った / 守りきった / 取られた）。

### クラッシュ・オブ・クランズの型を真似る（2026-11-24 決定／2026-11-25 追記）

「CoC みたい」ではなく、次の **意味**を RINGFALL の画面の型として採用する（TKT-192／TKT-195）。

| # | クラッシュ・オブ・クランズ側で効いていること | RINGFALL でそれが意味すること |
| --- | --- | --- |
| 1 | 攻めて終わったら、勝敗とトロフィーの増減が一枚で返る | **生還のリザルトを「その日の答え合わせ」の一枚にする。** 島の解放までの残り（前日との差）、島の知らせ（攻めた結果と攻められた結果）、トロフィーの前後と内訳、次の一手をこの順で並べる。 |
| 2 | 留守中に攻められた結果は、起動直後に防衛ログとして一度だけ出て、その後は履歴で見返せる | **起動して野営に立ったとき、留守中の対人結果をリザルトと同じ文の一枚で一度だけ出す。** 見たら信号所の島の知らせ（最大 10 件・永続）に控えが残る。事前の「来る遠征」警告画面は出さない。 |
| 3 | 目標の数字はどの画面でも常に見える | **「島の解放まで · 拠点 あと N」を野営の帯の横・レイド中の帯の横・リザルトに常に出す**（初日から。お隣に取られた拠点は N に数えない。「· 取られた N」は足さない）。決戦が開いていれば「決戦 · 発着場」。取り合う 4 拠点も N に数える。**トロフィーも HUD 左上に常時**（お隣の組み合わせの基準なので、信号所を開かなくても見える）。 |
| 4 | 攻撃が主な得、育てた村が他人の攻め先、トロフィーで相手選び、盾 | **方向 A（上）＋トロフィー／物資の分離（上）。** 迷ったらこちらの型を選ぶ。短いレイドや別入口は増やさない。 |

動詞は三つに固定する: **制圧**（核を取る）／**攻める**（他プレイヤー相手）／**解放**（島全体）。入口は一手につき一か所（倉庫のレベルは倉庫の棚だけ、出撃は門だけ）。

実装メモ（2026-11-24）: `liberationStatus()` / `liberationLine()` が N を求め、野営・レイド中・リザルトに出す。決戦が開いている日の出撃「目的」も「決戦 · 発着場」に揃える。島の知らせはリザルトと同じ文を `Profile.news`（v40・最大 10 件）に残し、予告（noticed）は一覧に出さない。タイトルから野営に立ったとき `syncOwn(..., false)` で留守中の対人を一度同期し、増えた控えがあればリザルトと同じ文の一枚（`Hud.awayResults`）を出す。見終わると野営に戻り、控えは信号所に残る。方向 A の実装は TKT-195 のスタック PR2〜6。

### 入手先の案内と倉庫が満杯のとき（2026-11-25 決定）

欲しい材料はゲーム側が案内し、倉庫が満杯でも物を黙って手放さない。

| # | 決めたこと | RINGFALL でそれが意味すること |
| --- | --- | --- |
| 1 | 持ち帰って倉庫に入りきらないときは、精算の直後に **倉庫の整理** を出す（モンハンの狩り後の整理） | 自動売却はやめる。持ち帰った物と倉庫を並べ、1 点ずつ売る／倉庫に入れる。確定するまで整理画面を出し直し、それまで門から出撃できない。整理待ちはセーブに残る（`Profile.pending`・v42）。預かり置き場は作らない。「残りを全部売る」は置かない。 |
| 2 | 中継ボックスは空きが足りなければ入る分だけ送り、残りはバッグに残す | 満杯（空き 0）では送れず、「中継ボックス · 倉庫が満杯」と出す。そのときもバッグを持ったまま切り上げて生還できる（持ち帰った物は整理へ）。 |
| 3 | 制圧で取った相手の島の守りやセーブ読込の上限超過も、満杯なら整理待ちへ | 黙って売らない・捨てない。 |
| 4 | 入手先の案内は「どこで取れる → 目標にする → 地図で見る → レイド中の印と進み具合 → 揃ったら次の一手」 | 決めていなければ次の一手の設備に要る物を自動で追い、手でも 1 つ選べる（`Profile.goal`）。出やすさは今の割合（%）のまま地域名を足す。商人で買えるならそれも出す。 |

文言の正は [glossary.md](glossary.md) と `view/copy.ts`。倉庫の容量の数字は [warehouse.md](warehouse.md)。

## 原則

各原則に「だからこうする／こうしない」を添える。矛盾する案が出たら、番号の小さい原則を優先する。

### 1. 拠点を育てるのが主役

自分の場所（野営・倉庫・工場・信号所など）に対して何かをするのが基本である。島での戦闘は、その結果として拠点が強くなるための手段。

| こうする | こうしない |
| --- | --- |
| 生還・中継ボックスでの送付・制圧が、工場の部隊・倉庫・次の出撃に繋がる | 「島で勝つこと」だけがゴールで、拠点に何も残らない設計 |
| 倉庫が満杯になったら、枠数が見える倉庫の棚からだけ倉庫を上げられる（[warehouse.md](warehouse.md)）。入りきらない物は **倉庫の整理** でプレイヤーが選ぶ（黙って売らない） | 作業場にも倉庫カードを並べて入口を二つにする。溢れをその場で売る・捨てる |
| 出撃前に今日の作戦・持ち出しが分かる | 拠点画面を飾りにし、レイドだけがゲーム本体に見える構成 |

### 2. 対人は非同期の守りと攻め

他プレイヤーとの関わりは、リアルタイムの撃ち合いではなく、攻めと守りに分かれた非同期の戦闘である（来る遠征をはねる、地図で攻める、島が留守の間に起きる攻防）。

| こうする | こうしない |
| --- | --- |
| 自分の島の前線に立つお隣の拠点を、普段の出撃で攻める。守りは自動で結果は島の知らせ | 他プレイヤーと同時に同じ戦場で撃ち合うモードを主軸にする。短いレイドや別入口を足す |
| 留守中の攻防はサーバー／島のルールが処理する | 「いま相手がオンラインだから戦える」を前提にする |
| 対人の結果は拠点・島の持ち分に戻る。競争の板（ランキング）は副次で、解放や拠点の結果から出す。トロフィーはお隣の組み合わせにも使う | 対人専用ロビーや、ランキングがメイン進行を決める設計 |

### 3. マルチは線の中に溶かす

マルチプレイは、覚える別モードや特別な操作として出さない。既存の出撃・持ち帰り・拠点の線の中で、自動または受動に起きる。

| こうする | こうしない |
| --- | --- |
| 中継ボックスで倉庫へ送ると、島の守りへの引き回しが自動で積まれる | 「援助を残す」「物資を送る」など、覚える専用動詞・専用画面を足す |
| 他プレイヤーの気配は薄い痕跡など、見なくても進める受動表示 | マルチ専用の凡例・キー・チュートリアルを必須にする |
| 来る遠征は既存の地図・核の守りと同じ語彙で扱う | 「マルチの時間です」とモード切替する |

### 4. 次の一手は明確。全部は触ってから分かる

何も知らない人が画面を見て、ルールの全部が一目でわかる必要はない。代わりに、**いまやってほしい次のアクション**は常に一つ、はっきり示す。触りながら構造が分かる。

| こうする | こうしない |
| --- | --- |
| 目標カード・プロンプト・野営のヒントで「次」を1行 | 最初の画面にシステム説明・凡例・数値を並べる |
| 接近してから場所の名前と結果が分かる | 画面外の用語や内部名で説明する |
| 失敗しても同じ線に戻れる | 「理解してから出撃」を強いる長い説明 |

### 5. 体験は1本の線。場所のプライマリは1つ

体験の線は（上の「いまの主ゴール」の出撃側）:

```
出撃 → 島で前線を押す → 持ち帰る → 拠点が育つ
```

月次では「拠点が育つ」が島の解放と自軍の強化に繋がり、日次では他プレイヤーとの攻め（自分の島の前線に立つお隣の拠点を出撃で制圧・トロフィー）が同じ線に溶ける。

各場所には目的が一つあり、そこでできるプライマリな選択肢も一つ。同じ場所に覚える動詞を並べない。

| こうする | こうしない |
| --- | --- |
| 中継ボックスは「倉庫へ送る」か「切り上げて生還」のどちらか（バッグの状態で決まる） | 同じ箱で送る／援助／拾う／印を付けるを並べる |
| 核は制圧 | 核の周りにマルチ専用の別操作を足す |
| 信号所は島の知らせ・お隣・トロフィー。攻めは門からの出撃。出撃は門だけ | 信号所に「遠征に出す」「出撃」を並べて攻める入口を分裂させる |
| 場所ごとに「表示名／できること／結果」が言える | 「ここは便利なハブ」として機能を詰め込む |

詳細な場所表は [ux-design.md](ux-design.md)。マルチの一本化は [multiplayer-experience.md](multiplayer-experience.md)（**方向 A「お隣は前線に立つ」採用**）。

### 6. 覚えさせる名前と操作を増やさない

新しい用語・キー・モードはコストが高い。「新しい用語が4つ」は多すぎる、という反応を基準にする。既存の語彙（使う、中継ボックス、倉庫へ送る、切り上げる、遠征、来る遠征、攻める）に寄せる。内部用語をプレイヤーに見せない。

| こうする | こうしない |
| --- | --- |
| brief にある表示名（中継ボックスなど）をそのまま使う | デポ、pad、parcel、援軍寄付などの内部名／開発語を UI に出す |
| 新機能は既存の「使う」に乗せるか、完全に自動にする | 機能ごとに新しい名詞と専用キーをセットで追加する |
| 削れるなら削る。簡素化が機能追加より優先 | 「あると便利」で線の外の操作を残す |

### 7. 操作は E かクリック／タップで完結する

特殊キー（Shift+E など）は避ける。キーボードでもタッチでも、同じ「使う」で遊べる。

| こうする | こうしない |
| --- | --- |
| 使用キー（E）／タップでプライマリを実行 | Shift+E、長押し＋別ボタン、マルチ専用ジェスチャを必須にする |
| 対象が重なるときは切替（T／画面の切替）で選ぶ | 修飾キーで別の動詞に切り替える |
| タッチレイアウトでも同じ Input に落とす | PC 専用のキー組み合わせを前提にする |

### 8. UI はまとまりを優先する。判定はシビアにしない

画面をごちゃごちゃさせない。インタラクト対象が重なっても、プレイヤーが「なぜこれが選ばれたか」で困らない。システム全体の一貫性を、個別の便利さより重視する。

| こうする | こうしない |
| --- | --- |
| プロンプトは「場所 · 結果」の1行 | チップ・凡例・バッジをヒーローや照準周りに重ねる |
| スコアとヒステリシスで対象を安定させる（ux Round 1） | 微移動で対象がチカチカ切り替わる |
| 線に乗らない情報は出さないか、受動の薄い絵にする | 全部のシステムを常時表示して「分かった気」にさせる |

## 判断に迷ったときのチェックリスト

新しい案・PR・文言を入れる前に、上から順に確認する。一つでも「いいえ」なら、削る・自動化する・既存語に寄せる・見送りする。

1. **拠点に戻るか？** — この行為の結果は、野営・倉庫・工場・島の持ち分のどれかに残るか。
2. **線に乗るか？** — 出撃 → 前線 → 持ち帰り → 拠点、のどこかに自然に置けるか。線の外なら別モードになっていないか。
3. **プライマリは1つか？** — その場所で覚える動詞は一つだけか。バッグの状態で文が変わるのはよい。別操作が増えるのはだめ。
4. **新しい名前／キーが増えていないか？** — 画面に出る新語はゼロが理想。特殊キーや「マルチ用の操作」を足していないか。
5. **内部用語が漏れていないか？** — デポ、pad、parcel などを UI・PR・報告に書いていないか。プレイヤー向けは中継ボックスなどの表示名か。
6. **次の一手が一行で言えるか？** — 「ここは何か」「使うと何が起きるか」を一行で示せるか。説明書が要るならまだ早い。
7. **タッチでも同じか？** — E またはタップだけで足りるか。修飾キー前提になっていないか。
8. **対人がリアルタイム必須になっていないか？** — 他プレイヤーとの関わりが、非同期の攻め／守りに収まるか。
9. **簡素化を犠牲にしていないか？** — 「あると便利」より「線が一本のままか」を優先したか。
10. **全部わからなくてよいか？** — 初見で全部説明する代わりに、触れば次が分かるか。
