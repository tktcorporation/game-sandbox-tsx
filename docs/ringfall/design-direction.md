# RINGFALL 設計方針

この文書は、RINGFALL の体験をどう組み立てるかの判断基準である。機能仕様（brief・island・multiplayer）や画面の細部（ui・ux-design）より先に読む。迷ったときはここへ戻る。

関連: [ux-design.md](ux-design.md)（体験の線と場所のプライマリ）、[glossary.md](glossary.md)（プレイヤー向け用語の正本）、[multiplayer-experience.md](multiplayer-experience.md)（マルチ体験の一本化）、[game-design-review.md](game-design-review.md)（楽しさ・進行・動機の点検・実装前）、[simplify-candidates.md](simplify-candidates.md)（簡素化の候補と決定・依頼板／反応型守り／島の出来事／夜の襲撃削除）、[raid-loot.md](raid-loot.md)（他プレイヤー拠点の制圧戦利品）、[warehouse.md](warehouse.md)（倉庫のレベル）、[brief.md](brief.md)、[ui.md](ui.md)、[multiplayer.md](multiplayer.md)、[island-v2.md](island-v2.md)。

**簡素化の決定（要約・2026-11-24）:** 外した機能はコードごと削除する（`FEATURES` フラグは使わない）。復活は Git 履歴（削除直前のコミット）から。依頼板（入門・今日の依頼・物語）、反応型の対人守り（来る遠征の予告→核で固めるの迎撃 UI）、島の出来事（破片の落下・嵐・回収部隊）、**夜の襲撃**（今夜の狙い・日をまたいでの拠点喪失）、**地図の机**は削除済み（前スタック PR1〜4）。**出撃の入口は門だけ**（車両の出撃導線・設備は削除）。**核 · 固める**（来る遠征向けの非同期閉門）も削除済み（§0g）。出撃・島眺めは **門**、トロフィー・島の知らせ・島の守りは **信号所**。詳細は [simplify-candidates.md](simplify-candidates.md) §0／§0b／§0c／§0d／§0e／§0f／§0g、[pvp-clarity.md](pvp-clarity.md)。

**お隣は自分の島の前線に立つ（方向 A・2026-11-25／TKT-195 → 作り順②）:** 外側の拠点をお隣と取り合い、普段のレイドでその核を制圧することが攻めになる。短いレイド・「○○の前線」・出ている遠征・遠征に出すはコードごと削除（スタック PR6）。取り合い対象の拡大は作り順②。詳細は下の「お隣は前線に立つ」と「島は終わりなく育てる」、[multiplayer-experience.md](multiplayer-experience.md)、[multiplayer.md](multiplayer.md)。

**本物のお隣との取り合い（2026-11-25／TKT-201）:** 取った取り合う拠点は相手の島の向かいの拠点へ写す。お隣は週ごとにお互いを引き合う。攻めの勝ち負けは守り側の島の知らせと起動時の一枚へ、攻め手の名前で送る。トロフィーの幅は相手の実トロフィーで決める（取れなかった攻めは減らない）。詳細は下の「本物のお隣との取り合い」。

**マルチのやり方が分かるように（2026-11-25／TKT-204）:** 地図の四隅の「お隣の島」と「海の道」は消えた遠征の名残で、線の先へ行けず何も起きない。攻め先は海岸の取り合う拠点そのものだと分かる印・入口・文言・初回案内・やり返すまでを一本にする（案 A〜G）。迷ったら CoC 寄り。詳細は下の「マルチのやり方が分かるように」。

**島は終わりなく育て、部隊戦へ力を出す（2026-11-25）:** 長期の軸は**自分の島を終わりなく育て、外側の拠点を保ち、部隊戦で力を出す**こと。**島の解放は外す**（作り順①・コード削除済み）。リセットも、解放のあとに野営・工場を初めに戻す周も、シーズンも無い。外側の拠点はすべて他プレイヤーに取られうる。内側の拠点と野営・倉庫・作業場・工場は取れない。育った島は別マップの部隊戦（4 対 4・空きは AI）の力になる。持ち時間の得点は直近数日の窓だけを数え、部隊戦の点は数日の戦いの終わりに精算する。詳細は下の「島は終わりなく育てる」。

用語の約束: プレイヤーが画面で見ない内部名（depot / pad / parcel など）を、UI・PR・報告・この文書のプレイヤー向け説明に使わない。荷物を送る場所は brief どおり **中継ボックス**。画面に出す語は [`src/ringfall/view/copy.ts`](../src/ringfall/view/copy.ts) と [glossary.md](glossary.md) を正とする（`npm run lint:ringfall-copy`）。

## 何を目指すか（参考の「意味」）

参考はスーパーセル（特にクラッシュ・オブ・クラン）のゲームデザインである。  
「クラッシュ・オブ・クラン風」とだけ書いて終わらせず、会話で拾った次の意味を RINGFALL の方針とする。

| スーパーセル側で効いていること | RINGFALL でそれが意味すること |
| --- | --- |
| 自分の村が主役 | **基本は自分の場所（拠点・野営・工場）に対して何かをする。拠点を育てるのが主役。** 島でのレイドは、その育成のための出撃である。 |
| 対人は守りと攻めに分かれ、非同期 | **他プレイヤーと直接リアルタイムで撃ち合うことはほとんどない。** 守りは自動（留守中に解決、結果は後から島の知らせで見る）。攻めだけ能動。クラッシュ・オブ・クランズの攻守と同じ型（[pvp-clarity.md](pvp-clarity.md)）。 |
| マルチは日常プレイの中に溶ける | **マルチは別モードでも特別な操作でもない。** 出撃・持ち帰り・拠点の育ちの線の中に、自然と入ってくる。 |
| 最初は全部わからなくてよい | **一目で全部理解できなくてもよい。** ただし、いまやってほしい次の一手は画面上で明確で、触っていくうちに仕組みが分かっていく。 |

RINGFALL は一人称の PvE レイドを持つが、長期の軸は「自分の島を終わりなく育て、拠点を保ち、部隊戦で力を出す」ことであり、他プレイヤーとのリアルタイム撃ち合いは主軸ではない。

## いまの主ゴール（CoC 型・確定／2026-11-25 更新）

クラッシュ・オブ・クランズ的な体験を進める。**メインは自分の島を終わりなく強くすること。** 資源を集めて作業場・工場・ポーチを育て、外側の拠点をできるだけ長く保ち、その力が部隊戦に乗る。他プレイヤーは外側の拠点を取りに来るし、こちらもトロフィーの近い相手の外側を攻める。ランキングのような競争層は副次（持ち時間は直近数日の窓、部隊戦の点は数日の戦いの終わりに精算）。島の解放・決戦・次の周・シーズンによるリセットは**しない**（解放のコード削除済み。下の「島は終わりなく育てる」）。

### 体験のループ（一文）

```
資源を集める → 自軍（工場・作業場・ポーチ）を強くする → 外側の拠点を保つ／取り返す → 部隊戦で力を出す
```

出撃の線（変わらない）はこのループの「資源を集める／前線を押す」の手段:

```
出撃 → 島で前線を押す → 持ち帰る → 拠点が育つ
```

| 層 | 何か | 画面の語 |
| --- | --- | --- |
| **長期の軸** | **自分の島を終わりなく育てる**（リセットも、解放のあとに野営・工場を初めに戻す周も無い） | 島・拠点・作業場・工場・レベルを上げる |
| **手段（育てる）** | **作業場**と**工場**と**ポーチ**（自軍のロボット・設備・持ち帰り枠） | 作業場・工場・ポーチ・レベルを上げる |
| **日次の対人** | **外側の拠点の取り合い**（攻めは門からの出撃。守りは自動）。保った力が部隊戦へ | 攻める・前線・島の知らせ・部隊戦 |
| **副次の競争** | **トロフィーと持ち時間・部隊戦の評価**（相手選びにも使う） | 拠点を取ると増え、守りきると少し増え、取られると減る。持ち時間は直近数日の窓。部隊戦の点は数日の戦いの終わりに精算 |

だからこうする／こうしない:

| こうする | こうしない |
| --- | --- |
| 一文ゴールは「自分の島を育て、外側の拠点をできるだけ長く保つ」 | 「島の解放」や決戦・次の周を今月の勝ちにする |
| 作業場／工場は拠点の守りと部隊戦の力のための手段として見せる | 箱集めだけがゴールに見える |
| 他プレイヤーとの攻めは **普段の出撃** で外側の拠点を制圧する。守りは自動。部隊戦は別マップ | 島の解放で野営・工場を初めに戻す。短いレイド・「○○の前線」の別入口（削除済み）を戻す |
| ランキングはトロフィーと持ち時間（直近の窓）・部隊戦の精算で、島を強くした結果の副次層 | シーズン終了で外側の持ち主を一斉に戻す。ランキング専用モードを主軸にする |

**ランキング＝トロフィー（確定）:** 取り合う拠点を取ると増え、守りきると少し増え、取られると減る（二重計上なし）。お隣の組み合わせはトロフィーが近い順（拠点数の週次ペアリングは置き換え）。常時表示（HUD 左上・地図のお隣）。詳細は下の「トロフィーと物資」。  
**攻め＝自分の島の前線（方向 A → 作り順②）:** 外側の拠点すべてをお隣と取り合う（内側の拠点と野営・倉庫・作業場・工場は取れない）。門から普段のレイドでその核を制圧することが攻め。短いレイド（旧 X2）と「○○の前線」は削除。信号所ボタンは置かない。詳細は下の「お隣は前線に立つ」と「島は終わりなく育てる」。  
**率いる遠征（段階 6）は廃止のまま** — 写し全体・信号所出撃は戻さない。

## 島は終わりなく育てる（2026-11-25 決定）

マルチを中心に据えたうえで、島の解放と次の周が「また一から」に聞こえて分かりにくく、自分の野営・工場を戻す利点も薄い、という判断。**作り順①（島の解放を外す）はコード削除済み**（`FINALE` / 決戦 / リセット / 強度+／帯の「あと N」）。タイタンと発着場はボス拠点・着陸・戦利品として残す。

| # | 決めたこと | RINGFALL でそれが意味すること | 理由 |
| --- | --- | --- | --- |
| 1 | **島の解放を外す** | 決戦・タイタン倒しによる島全体の解放、次の周での拠点・工場の初期化、帯の「島の解放まで · 拠点 あと N」をゴールにしない。**削除済み** | マルチが中心だと、解放して野営・工場を戻すメリットが薄く、「もう一度始める」が何を指すか分からなくなる |
| 2 | **自分の島は終わりがない** | クラッシュ・オブ・クランズの村と同じく、島は育ち続ける。リセットも、解放のあとに野営・工場を初めに戻す周も無い | 育てたものが残り続けるのが主役の体験 |
| 3 | **外側の拠点はすべて取られうる** | 海に面した 4 つ（観測所・浄水場・ロボット工場・追跡レーダー）に限らず、外側に面した拠点は他プレイヤーが核 · 制圧で取れる。**内側の拠点、野営、倉庫、作業場、工場は取れない** | 攻め先を海岸だけに閉じると、育った島の守りどころが狭すぎる。内側と野営まわりは「自分の村」として残す |
| 4 | **育った島が部隊戦の力になる** | 自分の島で持つ拠点が多いほど、部隊戦での力が上がる。強いプレイヤーの島へ他が攻めて力を削ぎ、取り合いが自分の島の上で起きる。狙いは**できるだけ長く自分の陣地を保つこと** | 拠点の意味が「解放までの数」ではなく「部隊戦と守り」に繋がる |
| 5 | **部隊戦は普段の地図とは別の場** | 部隊戦は自島のレイド地図とは別マップ。最初から 4 対 4。空き枠は AI の味方で埋める。1 回は数日で終わり、長く引きずらない。**その数日の戦いの終わりに部隊戦の点を精算する** | 普段の出撃と部隊戦の目的を分け、疲労を抑える。シーズン無しでも区切りを部隊戦の期間に置く |
| 6 | **攻め先の相手選び（仮）** | マッチングは今の相手チームを優先するが、トロフィーが近い人なら誰でも外側の拠点を攻めうる。**仮置きで、あとで変えうる** | チーム戦の緊張と、トロフィー帯の日常攻めの両方を試す |
| 7 | **陣地の力は部隊戦だけに効く** | 持つ拠点が多いと部隊戦の部隊が厚くなる。その厚みは部隊戦の場にだけ乗る。持ち帰る物の量は**ポーチの枠を上げる**ことで増え、部隊戦の力とは別の線 | 「戦力」と「持ち帰り」を混ぜないと、強い島が全部得になる |
| 8 | **シーズンは無い** | シーズン終了も、外側の拠点の持ち主の一斉リセットも無い。**作り順に「シーズン精算」の段は置かない** | 終わりなく育てる（#2）と矛盾させない |
| 9 | **雪だるまを抑えるガード（方向・数値は未定）** | 攻められたあとしばらく守られる／内側は取れない／一度に失う量に上限／先頭への懸賞金／近い強さのチーム同士、などを置く。数字は後で決める | 強い島が一方的に広がり続けないようにする |
| 10 | **得点は持ち時間と部隊戦を厚く** | いま何拠点持っているかより、**どれだけ長く持ったか**と部隊戦の結果を得点に厚く載せる。シーズンが無いので、持ち時間は**直近数日の窓だけ**を数える（ずっと前の持ち分は加点しない）。部隊戦の点は **#5 の数日の戦いの終わり**に精算する | 「長く保つ」が狙いになり、瞬間の拠点数だけの競争にならない。無限に積み上がる通算にもしない |
| 11 | **作り順（方向）** | ①島の解放を外す（**済み**） → ②取り合いを外側の拠点すべてへ広げる（**済み**・`sim/contested-outer.ts`） → ③守りと一度に失う上限（**済み**・`meta/outer-guard.ts` / `OUTER_GUARD`） → ④ 4 人チーム（空きは AI）→ ⑤部隊戦の別マップ → ⑥力・相手選び・持ち時間の得点、の順で積む。**シーズン精算の段は入れない** | ゴールの誤解を先に消し、取り合いの板を広げてからチーム戦を乗せる。シーズン無し（#8）と揃える |

だからこうする／こうしない:

| こうする | こうしない |
| --- | --- |
| 野営・リザルトの主数字を「持っている外側の拠点」「直近の持ち時間」「部隊戦」へ寄せる（実装は後） | 「島の解放まで · 拠点 あと N」を今月の勝ちとして残す |
| 外側は取られうる／内側と野営・倉庫・作業場・工場は取れない、を案内の正とする | 発着場以外は全部取れる、または海岸 4 つだけのまま広げるのを止める |
| 部隊戦の力とポーチの持ち帰りを別の線にする | 拠点が多いほど持ち帰りも部隊戦も両方厚くなる一本化 |
| シーズン終了で持ち主を戻さない。持ち時間は直近数日の窓、部隊戦の点は数日の戦いの終わりに精算 | 月次や周次のソフトリセットを競争の芯にする。通算の持ち時間を無限に積む。作り順にシーズン精算を足す |

先の節「お隣は前線に立つ」（海岸 4 拠点・方向 A）は、この節の **②に至る途中の仮置き** だった。**作り順②は実装済み**（`sim/contested-outer.ts`）: 取り合う拠点は外側の拠点すべて。判定は地図データから — 解放可能な拠点の凸包の頂点、または中心が海岸から 110 m 以内（`offshore > −110`）、または世界矩形（`WORLD`）の端から 150 m 以内。内側の拠点（補給所・採掘場・中継塔・コンテナヤード・製錬所・缶詰工場・冷凍倉庫・中央駅・立体駐車場・管制センター・組立棟）と野営・倉庫・作業場・工場は取れない。お隣スロットの海路 4 面（観測所・浄水場・ロボット工場・追跡レーダー）は航路開閉用に残す。地図では自分の取り合う拠点に細い破線の輪（他プレイヤーに取られうる印）。

**作り順③は実装済み**（`meta/outer-guard.ts` / `OUTER_GUARD`、既存の `IslandState.shielded` を拡張）:

| 定数 | 値 | 意味 |
| --- | --- | --- |
| `OUTER_GUARD.lossCap` | **1** | 1 UTC 日に失える外側の拠点の上限 |
| 島の盾の長さ | **その UTC 日の終わりまで**（次の UTC 0:00） | 外側を 1 つ取られたら、残りの自分の外側拠点は同日中は取れない |

判断: CoC の「取られたら盾が張り、その日はもう取られない」に寄せ、既存の拠点単位のその日の盾（取られた拠点そのもの）に **島全体の旗**（`shielded.island`）を足した。別システムのタイマーは置かない。野営の日の行と信号所に「守り中 · あと H:MM」／「今日取られた n/1」を出す。チーム・部隊戦の場・先頭への懸賞金はまだ入れない（④以降）。

## お隣は前線に立つ（方向 A・2026-11-25／TKT-195）

クラッシュ・オブ・クランへ寄せるための**暫定の一歩**。迷ったら CoC 側を選ぶ。

| CoC で効いていること | RINGFALL（方向 A）でそれが意味すること |
| --- | --- |
| 攻撃が資源・進行の主な入り口 | **攻める＝前線を押す。** 取った拠点は自分の陣地になり部隊戦の力に繋がり、島の守りが倉庫へ届く（「あと N」は島の解放のゴールとしては使わない） |
| 自分の村が他人の攻め先 | **育てた工場の部隊と島の守りが、お隣から見た守備隊になる** |
| 防衛ログ | 起動時の一枚と信号所の島の知らせ（「{誰}が{拠点}を攻めた · 守りきった」など） |
| トロフィーで相手選び | **トロフィーが近い人がお隣** |
| シールド | **取られた拠点はその日のうちは取られない** |
| 勝ち＝トロフィー、資源庫＝物資 | **拠点の持ち主が変わるとトロフィー。核 · 制圧の手応えは物資（倉庫へ）** |

一文の一日:

```
門 → 出撃地図（お隣の拠点も普通の拠点）→ 自分の島のレイドで核 · 制圧 → リザルト（あと N → 島の知らせ → トロフィー内訳）
```

決まり（画面に出さない設計名は使わない。拠点はいつもどおりの名前＋持ち主）:

1. **取り合う拠点** — **外側の拠点すべて**（作り順②・地図データから導出。海または地図境界に面する）。海路のお隣スロットは従来どおり 4 面（観測所・浄水場・ロボット工場・追跡レーダー）。持ち主は一人。
2. **攻め** — 門からの普段のレイドでその核を制圧すること。別の入口・別の舞台は無い。

## トロフィーと物資（CoC の勝ち／資源庫・2026-11-25／TKT-201 追記）

ユーザーの声: トロフィーがどこにあるかわからない。攻めたときと守ったときで増減してほしい。核を取ったときは物資多め、トロフィーを取ったときはトロフィーが増えるバランス。確認済み: **同じ攻めで、拠点を取ったらトロフィー、核を制圧したら物資多め**。迷ったらクラクラ寄り。

| CoC | RINGFALL |
| --- | --- |
| 攻撃勝利 → トロフィー増 | **取り合う拠点が自分のものになる** → トロフィー増（`TROPHY.base` 30 ± 相手との差で最大 20）。相手の実トロフィーを使う（上の §3） |
| 防衛勝利 → トロフィー少し増 | **お隣の攻めを守りきった**（島の知らせ「… · 守りきった」とセット）→ `TROPHY.defend` 10 |
| 拠点を取られる → トロフィー減 | **取り合う拠点を取られる** → トロフィー減（攻めと同じ幅） |
| 資源庫から資源 | **核 · 制圧** → その拠点の島の守りが倉庫へ。空でも `SEIZE.emptyReserve`、加えて `SEIZE.bonus`（AI の拠点も含む） |
| トロフィーはホーム画面左上 | **HUD 左上に常時。** 地図ではお隣の名前の横にも相手のトロフィー |

コード上「拠点を取る」と「核を制圧」は同じ操作（核のメーター）だが、精算では分ける:

- **トロフィー** — 相手持ちの**取り合う拠点**が自分のものになったときだけ（所有の変化）。幅は相手の実トロフィーとの差。
- **物資の上乗せ** — 核を制圧したとき（`seizeRivalLoot`。AI 含む。クラクラは NPC 村からも資源が取れるため）。

攻め側が守りきれなかったとき（0 星相当）のトロフィー減は**採らない**。RINGFALL の攻めは短い専用レイドではなく普段の出撃の核 · 制圧なので、「取れなかった＝増えない」を負けとする。防衛側の `defend` だけ足す。

数値の正本は `src/ringfall/meta/trophies.ts`（`TROPHY` / `SEIZE`）。リザルト・起動時カード・島の知らせのトロフィー行は攻め／守りの内訳が分かる形（`trophyLine`: 取った / 守りきった / 取られた）。

## クラッシュ・オブ・クランズの型を真似る（2026-11-24 決定／2026-11-25 追記）

「CoC みたい」ではなく、次の **意味**を RINGFALL の画面の型として採用する（TKT-192／TKT-195）。

| # | クラッシュ・オブ・クランズ側で効いていること | RINGFALL でそれが意味すること |

| 2 | 留守中に攻められた結果は、起動直後に防衛ログとして一度だけ出て、その後は履歴で見返せる | **起動して野営に立ったとき、留守中の対人結果をリザルトと同じ文の一枚で一度だけ出す。** 見たら信号所の島の知らせ（最大 10 件・永続）に控えが残る。事前の「来る遠征」警告画面は出さない。 |

## 目標への案内（2026-11-25 決定）

プレイヤー報告: どこで取れるで「タイタン · ダム湖」を見ても、タイタンもダム湖も分からない。地図で見ても着地後は前線の核だけが羅針盤に出て、迷う。

参考は Destiny（追う目的地が羅針盤の印）／モンハン・原神（狩り・マーカーの距離）／クラッシュ・オブ・クラン（攻撃先は一目で追える）。迷ったらその型を選ぶ。

| # | 決めたこと | RINGFALL でそれが意味すること |
| --- | --- | --- |
| 1 | **地図で見る**は一手で目標も付ける | 入手先の行で地図で見るを押すと、その材料を目標にし、門の出撃地図をその拠点へ開く。すでにその目標ならボタンは「目標にしている」と分かり、地図で見ても同じ一手（目標は付けたまま出撃地図へ）。目標にする単体も同じ表示。 |
| 2 | レイド地図とミニマップに目標を出す | 目標の材料が出る拠点に印（輪・ピン）。ロボットだけの入手先（タイタン＝発着場）も印の対象に含める。画面外なら端矢印。目標の拠点名・地域名（ダム湖・発着場・タイタン側の印）は重なりで落とさない。ミニマップにも同じ印。 |
| 3 | HUD は目標の向きと距離を出す | 着地時に「{地域}に着いた。{入手先}は{拠点}（○ m）」の一行。レイド中の羅針盤は「{入手先} ○ m」（例: タイタン 474 m）。 |
| 4 | 目標と前線の共存 | **目的カードは前線（その日の島の仕事）のまま。** 羅針盤の印は、目標が付いていてまだ足りないあいだは目標の入手先へ向ける。核の制圧の最中・自拠点を守る最中は例外で、目的カードの行き先を羅針盤にも出す（緊急の一手）。脅威の矢印・地図の前線リングはそのまま。フィールドの光の柱は変えない。 |

だからこうする／こうしない:

| こうする | こうしない |
| --- | --- |
| 地図で見る＝目標＋出撃地図の一手 | 地図で見るは近い入口だけ選び、目標は別ボタン必須 |
| 羅針盤は目標の入手先名＋距離 | 前線の核だけを常に指し、目標は地図の薄い輪だけ |
| 目的カードは前線、羅針盤は目標（緊急時は前線へ） | 目的カードを材料ハント専用に差し替える／印を二つ並べる |
| タイタンなどロボット入手先も印と距離の対象 | 補給箱のテーブルだけを目標拠点とみなす |

実装は積み上げ PR（docs → 地図で見る＝目標 → 地図の印 → HUD）。フィールドの光の柱・出撃地図の枠ズーム・入手先行の文言そのものは触らない。

## 育てる入口は作業場に寄せる（CoC 型・2026-11-25 決定／TKT-192 を覆す）

クラッシュ・オブ・クランズでは、村の建物の強化は一つの「育てる」場所に集まる。RINGFALL もそれに寄せる。

| CoC で効いていること | RINGFALL でそれが意味すること |
| --- | --- |
| 建物のレベル上げは村の中で同じ操作 | **隠れ家の設備（倉庫を含む）のレベル上げは作業場だけ。** 工場は工場。倉庫の棚・商人の屋台・倉庫の整理には上げるボタンを置かない |
| 資源庫の中身を見る場所と、庁舎で建てる場所は分かれる | **倉庫の棚**は中身・持ち出し・無線。**作業場**で倉庫を含む設備を上げる。棚・屋台・整理・作業場の倉庫カードには枠数（使う数 / 上限）と満杯時の案内を出す |
| 満杯なら資源を使うか倉庫を広げる | 満杯の案内は「売るか、作業場で倉庫を上げる」（最上段なら「売る」だけ）。次の一手も倉庫が作れるときは他設備と同じ「次：作業場 · レベルを上げる」 |

だからこうする／こうしない:

| こうする | こうしない |
| --- | --- |
| 作業場の一覧に倉庫カードを戻し、作業場の ▲ に倉庫の作れる段を数える | 倉庫の棚だけに上げる入口を置く（旧 TKT-192） |
| 倉庫の棚の右列は無線＋持っていく物だけ（タイトルも中身に合わせる） | 棚に倉庫のレベルカードや `▲ LvN` の野営マークを出す |
| 作業場の倉庫カード／パネルに枠のバーを出す | 整理画面に「空きが足りない：売るか、作業場で倉庫を上げる」の一行を足す（不採用） |

詳細・数字・文言の正本は [warehouse.md](warehouse.md)。

## 原則

各原則に「だからこうする／こうしない」を添える。矛盾する案が出たら、番号の小さい原則を優先する。

### 1. 拠点を育てるのが主役

自分の場所（野営・倉庫・工場・信号所など）に対して何かをするのが基本である。島での戦闘は、その結果として拠点が強くなるための手段。

| こうする | こうしない |
| --- | --- |
| 生還・中継ボックスでの送付・制圧が、工場の部隊・倉庫・次の出撃に繋がる | 「島で勝つこと」だけがゴールで、拠点に何も残らない設計 |
| 倉庫が満杯になったら **作業場** で倉庫を上げる（[warehouse.md](warehouse.md)）。枠数は倉庫の棚・商人・整理・作業場の倉庫カードで見える。入りきらない物は **倉庫の整理** でプレイヤーが選ぶ（黙って売らない） | 倉庫の棚・整理・商人にも上げるボタンを置く。溢れをその場で売る・捨てる |
| 出撃前に今日の作戦・持ち出しが分かる | 拠点画面を飾りにし、レイドだけがゲーム本体に見える構成 |

### 2. 対人は非同期の守りと攻め

他プレイヤーとの関わりは、リアルタイムの撃ち合いではなく、攻めと守りに分かれた非同期の戦闘である（来る遠征をはねる、地図で攻める、島が留守の間に起きる攻防）。

| こうする | こうしない |
| --- | --- |
| 自分の島の前線に立つお隣の拠点を、普段の出撃で攻める。守りは自動で結果は島の知らせ | 他プレイヤーと同時に同じ戦場で撃ち合うモードを主軸にする。短いレイドや別入口を足す |
| 留守中の攻防はサーバー／島のルールが処理する | 「いま相手がオンラインだから戦える」を前提にする |
| 対人の結果は拠点・島の持ち分に戻る。競争の板（ランキング）は副次で、拠点の持ち時間と部隊戦の結果から出す。トロフィーはお隣の組み合わせにも使う | 対人専用ロビーや、ランキングがメイン進行を決める設計。島の解放を競争の芯にする |

### 3. マルチは線の中に溶かす

マルチプレイは、覚える別モードや特別な操作として出さない。既存の出撃・持ち帰り・拠点の線の中で、自動または受動に起きる。

| こうする | こうしない |
| --- | --- |
| 中継ボックスで倉庫へ送ると、島の守りへの引き回しが自動で積まれる | 「援助を残す」「物資を送る」など、覚える専用動詞・専用画面を足す |
| 他プレイヤーの気配は薄い痕跡など、見なくても進める受動表示 | マルチ専用の凡例・キー・チュートリアルを必須にする |
| 来る遠征は既存の地図・核の守りと同じ語彙で扱う | 「マルチの時間です」とモード切替する |

### 4. 次の一手は明確。全部は触ってから分かる

何も知らない人が画面を見て、ルールの全部が一目でわかる必要はない。代わりに、**いまやってほしい次のアクション**は常に一つ、はっきり示す。触りながら構造が分かる。

| こうする | こうしない |
| --- | --- |
| 目標カード・プロンプト・野営のヒントで「次」を1行 | 最初の画面にシステム説明・凡例・数値を並べる |
| 接近してから場所の名前と結果が分かる | 画面外の用語や内部名で説明する |
| 失敗しても同じ線に戻れる | 「理解してから出撃」を強いる長い説明 |

### 5. 体験は1本の線。場所のプライマリは1つ

体験の線は（上の「いまの主ゴール」の出撃側）:

```
出撃 → 島で前線を押す → 持ち帰る → 拠点が育つ
```

長期では「拠点が育つ」が部隊戦の力と自軍の強化に繋がり、日次では他プレイヤーとの攻め（外側の拠点を出撃で制圧・トロフィー）が同じ線に溶ける。島の解放はゴールにしない。

各場所には目的が一つあり、そこでできるプライマリな選択肢も一つ。同じ場所に覚える動詞を並べない。

| こうする | こうしない |
| --- | --- |
| 中継ボックスは「倉庫へ送る」か「切り上げて生還」のどちらか（バッグの状態で決まる） | 同じ箱で送る／援助／拾う／印を付けるを並べる |
| 核は制圧 | 核の周りにマルチ専用の別操作を足す |
| 信号所は島の知らせ・お隣・トロフィー。攻めは門からの出撃。出撃は門だけ | 信号所に「遠征に出す」「出撃」を並べて攻める入口を分裂させる |
| 場所ごとに「表示名／できること／結果」が言える | 「ここは便利なハブ」として機能を詰め込む |

詳細な場所表は [ux-design.md](ux-design.md)。マルチの一本化は [multiplayer-experience.md](multiplayer-experience.md)（**方向 A「お隣は前線に立つ」採用**）。

### 6. 覚えさせる名前と操作を増やさない

新しい用語・キー・モードはコストが高い。「新しい用語が4つ」は多すぎる、という反応を基準にする。既存の語彙（使う、中継ボックス、倉庫へ送る、切り上げる、遠征、来る遠征、攻める）に寄せる。内部用語をプレイヤーに見せない。

| こうする | こうしない |
| --- | --- |
| brief にある表示名（中継ボックスなど）をそのまま使う | デポ、pad、parcel、援軍寄付などの内部名／開発語を UI に出す |
| 新機能は既存の「使う」に乗せるか、完全に自動にする | 機能ごとに新しい名詞と専用キーをセットで追加する |
| 削れるなら削る。簡素化が機能追加より優先 | 「あると便利」で線の外の操作を残す |

### 7. 操作は E かクリック／タップで完結する

特殊キー（Shift+E など）は避ける。キーボードでもタッチでも、同じ「使う」で遊べる。

| こうする | こうしない |
| --- | --- |
| 使用キー（E）／タップでプライマリを実行 | Shift+E、長押し＋別ボタン、マルチ専用ジェスチャを必須にする |
| 対象が重なるときは切替（T／画面の切替）で選ぶ | 修飾キーで別の動詞に切り替える |
| タッチレイアウトでも同じ Input に落とす | PC 専用のキー組み合わせを前提にする |

### 8. UI はまとまりを優先する。判定はシビアにしない

画面をごちゃごちゃさせない。インタラクト対象が重なっても、プレイヤーが「なぜこれが選ばれたか」で困らない。システム全体の一貫性を、個別の便利さより重視する。

| こうする | こうしない |
| --- | --- |
| プロンプトは「場所 · 結果」の1行 | チップ・凡例・バッジをヒーローや照準周りに重ねる |
| スコアとヒステリシスで対象を安定させる（ux Round 1） | 微移動で対象がチカチカ切り替わる |
| 線に乗らない情報は出さないか、受動の薄い絵にする | 全部のシステムを常時表示して「分かった気」にさせる |

## 判断に迷ったときのチェックリスト

新しい案・PR・文言を入れる前に、上から順に確認する。一つでも「いいえ」なら、削る・自動化する・既存語に寄せる・見送りする。

1. **拠点に戻るか？** — この行為の結果は、野営・倉庫・工場・島の持ち分のどれかに残るか。
2. **線に乗るか？** — 出撃 → 前線 → 持ち帰り → 拠点、のどこかに自然に置けるか。線の外なら別モードになっていないか。
3. **プライマリは1つか？** — その場所で覚える動詞は一つだけか。バッグの状態で文が変わるのはよい。別操作が増えるのはだめ。
4. **新しい名前／キーが増えていないか？** — 画面に出る新語はゼロが理想。特殊キーや「マルチ用の操作」を足していないか。
5. **内部用語が漏れていないか？** — デポ、pad、parcel などを UI・PR・報告に書いていないか。プレイヤー向けは中継ボックスなどの表示名か。
6. **次の一手が一行で言えるか？** — 「ここは何か」「使うと何が起きるか」を一行で示せるか。説明書が要るならまだ早い。
7. **タッチでも同じか？** — E またはタップだけで足りるか。修飾キー前提になっていないか。
8. **対人がリアルタイム必須になっていないか？** — 他プレイヤーとの関わりが、非同期の攻め／守りに収まるか。
9. **簡素化を犠牲にしていないか？** — 「あると便利」より「線が一本のままか」を優先したか。
10. **全部わからなくてよいか？** — 初見で全部説明する代わりに、触れば次が分かるか。
