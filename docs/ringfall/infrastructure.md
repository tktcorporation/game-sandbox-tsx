# RINGFALL infrastructure (#124, #134–#136, TKT-44)

This PR prepares a **single Worker**. No Cloudflare account operation or deployment has been performed. The [Cloudflare CLI `cf`](https://developers.cloudflare.com/cf/) is the open beta project CLI, separate from the Cloudflare OpenTofu provider. Its configuration and Build Output may change during beta.

This repository pins `cf` 1.0.0-beta.24, the Cloudflare Vite plugin 2.0.0-beta.v.8, and Vite 7.3.7. All were at least 14 days old on 2026-11-14, as required by `CLAUDE.md`. The local build used Node 24.22.0; verify a supported Node version in Workers Builds before changing its commands.

## Build and release entrypoints

The npm scripts are the repository's command contract. `npm run builds:build` runs the TypeScript check and `cf build --mode production`. It produces `.cloudflare/output/v0/` with mode `production`, including the Vite assets. `npm run builds:deploy` runs `cf deploy --prebuilt --mode production`: **it uploads and changes production traffic**. `npm run builds:version` runs `cf workers versions create --prebuilt --mode production`: **it uploads a version without switching production traffic**. Both upload commands require a matching Build Output from `builds:build` in the same job or restored artifact. `npm run deploy` combines the build and production deploy. `npm run dev` and `npm run preview:local` both run `cf dev` locally; neither is a Cloudflare Preview deployment. The old `vite preview` script is removed.

The version-only path is a non-production **upload**, not a working Preview for this Durable Object Worker: its Version URL is unsupported. A branch-isolated Worker Preview would be a different `cf previews deploy` workflow and may provision isolated resources. It is a future option requiring separate review of the actual preview model, D1/DO isolation, routes, quota and cost. No such command is installed as an npm script yet. Do not pass production Build Output to a new Preview with `--prebuilt`; Preview Build Output must be built for that purpose. The [cf prebuilt mode rule and Preview model](https://developers.cloudflare.com/cf/projects/) are the references.

The external Cloudflare Builds **build command** should eventually be `npm run builds:build`. Its production **deploy command** should be `npm run builds:deploy`; a legacy non-production branch using version-only upload should use `npm run builds:version`, with no claim of real Preview QA. The current production branch, branch filters, Preview model and saved commands are unverified. First inspect those settings and confirm which branch each trigger builds. Do not change any external command until that trigger's branch contains these scripts. Then align the commands once and read the saved values back. The outer Builds command is selected before `cloudflare.config.ts` is evaluated, so code cannot repair a saved Wrangler command automatically. Do not add a push-time self-updater. Workers Builds must use a supported Node version; `.node-version` requests 24.22.0, and `package.json` records the cf-supported engine range. Check the effective version in build logs.

## Ownership

| Item | Owner / source of truth |
| --- | --- |
| D1 `ringfall` database lifecycle | OpenTofu `infra/ringfall/main.tf`; name in `infra/ringfall/config.json` |
| D1 schema | `migrations/0001_init.sql`; explicit `cf d1 migrations` operation |
| Game Worker, `IslandDO` export and self binding, code, assets, versions and deployment | `cloudflare.config.ts`, `worker/index.ts`, Vite, and `cf` |

The root Worker exports `IslandDO` and binds to that class in the same Worker. `cf` declares its SQLite lifecycle with `exports.durableObject({ storage: "sqlite" })`, replacing the separate island Worker and its Wrangler v1 migration **in source only**. This does not authorize deletion or transfer of any real namespace or Worker. If an existing `ringfall-islands` Worker or DO namespace is found, stop and design its migration using Cloudflare's [transfer procedure](https://developers.cloudflare.com/cf/projects/cloudflare-config/#transfer-a-class-between-workers) before deploying. Do not infer that absence from this repository means absence in the account.

`cloudflare.config.ts` includes `DB` only when `RINGFALL_D1_DATABASE_ID` is set to a UUID. This prevents `cf deploy` from auto provisioning a D1 database when the OpenTofu-owned ID is not yet known. The name comes from the same JSON file that OpenTofu reads. No account or database ID is committed. `ISLAND` is a self binding to `IslandDO`. Vite owns the static assets output and preserves the three HTML entrypoints in `vite.config.ts`; the cf config owns asset runtime behavior and the `ASSETS` binding. `cf build` and `cf deploy --dry-run` validate Build Output without uploading. Production traffic and existing Workers Builds settings are unknown; this PR changes neither.

The old `wrangler.jsonc`, `islands/` Worker entry/config, and generated Wrangler config script were removed because the project is unreleased and the approved target is one cf Worker. The existing `worker/island.ts` rules and `worker/island-do.ts` implementation remain. The D1 migration remains the SQL source of truth. Cf expects the D1 **ID** in migration commands, and migrations are remote by default, so operators must take care with the commands below. See the [cf migration guide](https://developers.cloudflare.com/cf/wrangler/migrate/#d1-migrations).

## Staged release after separate approval

1. **DB** — In `infra/ringfall`, initialize a protected backend and verify the Cloudflare provider and account. If a `ringfall` D1 already exists, confirm its owner and import it with the provider's current import syntax. Otherwise review a create plan. Inspect the plan for replacement or deletion; `prevent_destroy` is only a safeguard. Apply only with explicit production authorization and record `tofu output -raw ringfall_database_id` privately.
2. **SQL** — Inspect the intended D1 and `migrations/0001_init.sql`; arrange a backup. From repo root run `cf d1 migrations list "$RINGFALL_D1_DATABASE_ID" --dir migrations` and, after review, explicitly run `cf d1 migrations apply "$RINGFALL_D1_DATABASE_ID" --dir migrations`. These target remote D1 by default; `--local` is only for local rehearsal. Verify the `players`, `island_summaries`, and `raids` tables before enabling `DB` on a deployment. A missing schema makes API writes fail with 503.
3. **Worker** — Check whether the old `ringfall-islands` Worker or namespace was actually deployed. If yes, stop for a separately reviewed data transfer plan. If no, verify `npm run builds:build` and a local `cf deploy --dry-run --prebuilt --mode production` with the actual D1 ID in a secure environment, inspect assets, routes and binding output, then deploy the single Worker only with separate authorization. Do not use a name-only D1 binding; cf may provision a resource for it. Update Workers Builds only after confirming its current configuration and deployment trigger and that its target branch contains the scripts.
4. **Real QA** — Complete a raid and verify `POST /api/island` succeeds instead of 202 (`no-database`) or 503 (`db-error`); query the actual D1 summary. Verify an island code and `GET /api/islands/<code>` returns 200. Use two browsers with separate storage to perform [#136](https://github.com/tktcorporation/game-sandbox-tsx/issues/136), including expedition, capture, retake and income. A newly claimed island cannot receive expeditions for **two days**. The screenshot gate suppresses server requests and is not evidence of real connectivity.

If any stage fails, stop before the next. Return the game Worker to a known good version/config if a deployment fails; preserve D1 and DO state while diagnosing. For a schema or data incident, use the reviewed backup and restore plan. Never delete D1, a Worker or a DO namespace as an automatic rollback.

Before production, review current [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/), [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) and [Workers Builds pricing](https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/), plus anonymous island claim abuse controls, alerts, permissions and operational ownership.
