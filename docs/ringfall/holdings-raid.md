# 島で漁り、お隣の陣地を攻める（方針・2026-11-27）

状態: **方針として採用**。実装はスタック PR で進行中（下の「作り順」）。  
関連: [design-direction.md](design-direction.md)（判断基準）、[multiplayer-experience.md](multiplayer-experience.md)・[pvp-clarity.md](pvp-clarity.md)（この方針で置き換わる部分がある）、[raid-loot.md](raid-loot.md)（星・トロフィー・制圧の戦利品はここから流用）、[glossary.md](glossary.md)。

**追記（2026-11-27）:** 大枠を三つ決めた（[glossary.md](glossary.md)「決めたこと」）。この文書の「お隣」は**別プレイヤー**（AI を含む）と読む。陣地を取りうるのは別プレイヤーだけで、島のロボットは陣地を取らない。拠点の収入は現実の時間で溜まり、攻められると持っていかれる。チーム・部隊戦（作り順④⑤⑥）は消す。日は現実の暦の日で、出撃で進まない。

---

## なぜ変えるか

いまの体験は「気持ちよさ」以前に、流れとして成立していない。原因は細部ではなく骨組みにある。

1. **一人用の脱出シューターの上に、CoC 型の取り合いを重ねている。** 倉庫・商人・貴重品・持ち帰りは「漁って生きて帰る」ための仕組みで、対人はその上に後から乗った。
2. **一回の出撃に目的が三つある。** 箱を漁って持ち帰る／ロボットの前線を押す（核）／お隣の外側の拠点を取る（トロフィー・部隊戦の力）。CoC は「攻める」一回で資源もトロフィーも入り、行動と結果が一本に揃う。RINGFALL では三つが時間と全滅のリスクを奪い合い、何を優先すればよいか分からない。
3. **育てる場所と攻められる場所が違う。** 育てるのは野営地（メニュー）、攻められるのは外側の拠点（レイドの中でしか見えない）、その間をつなぐ「工場の部隊が守っている」は見えない。
4. **「お隣が自分の島の前線に立つ」が想像しにくい。** 相手の場所へ行かず、自分の島にある相手の拠点を取る。誰かを攻めている実感が薄く、「前線」がロボットとの前線とお隣との取り合いの二つの意味を持つ。
5. **出口が三本ある。** 普段のレイド、別マップの部隊戦、自動の守り。

## 決定

**自分の島ではロボット相手に漁り、拠点を占領する。占領した拠点（陣地）が、他の人から攻められる場所になる。対人の攻めは、お隣の島の陣地へ短く出撃する。守りは自動。**

CoC の村に当たるのは**占領した陣地の並び**。野営地（柵の中）だけに縛られず、島で広げた陣地がそのまま「育てた自分の場所」であり「攻められる場所」になる。拠点は 100〜250 m の広さがあるので、攻めの舞台としてもそのまま使える。

| | 漁り（自分の島） | 攻め（お隣の陣地） |
| --- | --- | --- |
| 行き先 | 自分の島の 4 地域（いまのレイドのまま） | お隣の島の、その人が占領している拠点一つ |
| 敵 | ロボット（敵・はぐれ） | 持ち主の工場の部隊＋島の守り（自動で戦う）。ロボットの巡回・増援・狩りの一行は出ない |
| 入り方・出方 | 入口から歩いて入り、脱出地点か中継ボックスで出る | その拠点の**中継ボックスの前から始まり、中継ボックスで出る** |
| 目的 | 貴重品・材料を持ち帰る、拠点を占領して広げる | 核を制圧する（星 ★1〜3） |
| 持ち帰る | 貴重品・材料 | その陣地の島の守り（倉庫へ届く）＋トロフィー＋箱の中身 |
| 長さとリスク | 長い。全滅で荷物を失う | 短い（持ち時間 `SORTIE.time`）。時間切れは生還扱い（それまでの星で精算） |

一文のループ:

```
島で漁って拠点を占領する → 陣地が広がり、工場が育つ（＝他の人から見た攻め先と守りが厚くなる）
                         → お隣の陣地へ攻めに行く → 星・トロフィー・倉庫へ届いた → また育てる
留守中 … 自分の陣地が攻められ、工場の部隊と島の守りが勝手に守る → 結果は島の知らせ → やり返す
```

- 出撃の入口は**門のまま一つ**。出撃地図に島の入口と並べて「{誰}の{拠点}を攻める」を出す。新しい名詞は足さない。
- 攻め先は**持ち主が占領している拠点すべて**（外側・内側を問わない）。野営地・倉庫・作業場・工場は攻められない。
- 制圧された陣地は、持ち主の島で**ロボットの側に戻る**（取った人の物にはならない）。持ち主は自分の島のレイドで占領し直す。「前線」はロボットとの前線の意味だけになる。
- 盾と喪失上限（作り順③、`OUTER_GUARD`）はそのまま陣地に掛かる。取られたらその日は島全体が守られ、一日に失うのは最大 1。

## いまの仕組みの扱い

| いまの仕組み | 扱い |
| --- | --- |
| 外側の拠点の取り合い（お隣が自分の島の前線に立つ・作り順②） | **外す。** 自分の島にお隣の拠点は立たない。攻めはお隣の島へ出撃する |
| 星・トロフィー・制圧の戦利品（TKT-218/219、`raidOdds`・`SEIZE`） | **そのまま流用**し、攻めの出撃に付け替える |
| 守り中／今日取られた n/1（作り順③） | そのまま陣地に掛ける |
| 4 人チーム（作り順④） | 残す |
| 部隊戦・荒地の戦場（作り順⑤⑥） | 相手チームの陣地を攻め合う戦いに置き換える。別マップは要らなくなる |
| 島の知らせ・やり返す・偵察・リーグ | そのまま攻めの出撃に付け替える |
| 工場の部隊・島の守り | 自分の陣地の守備隊。攻めに来た相手と戦う |
| AI の島 | 占領した陣地を持つ AI の島として攻め先に出す |
| 島の Worker（`IslandDO`） | 攻めの結果（陣地を失った／守りきった）を持ち主へ届ける |

作り順②と⑤⑥のコードは、置き換えが済んだ段で**コードごと削除**する（`FEATURES` は使わない。復活は Git 履歴から）。

| # | 問い | いまの考え |

| 1 | 陣地の守りの組み方 | まず工場のレベルと島の守りから**自動で並べる**（いまの `defenceMembers()`）。配置の編集は流れが成立してから |

| 5 | 攻めの持ち時間 | 5 分を目安に sim で決める |

## 作り順（スタック PR）

各段は流れが一周するところまで作り、遊んで確かめてから次へ進む。

1. **方針（本紙）**
2. **sim: 陣地への攻めの出撃。**（済み・`scripts/ringfall-sortie.ts`） `newRun(..., { sortie })` で、相手の陣地の中継ボックスの前から始まり、守備隊だけが立ち、持ち時間で終わる。星は既存の採点
3. **meta: 攻め先と精算。**（済み・`meta/sortie.ts`、Profile v49、`scripts/ringfall-sortie-settle.ts`） AI の島の占領陣地を攻め先として並べ、攻めの精算は自分の島の持ち主を動かさず、星・トロフィー・倉庫へ届いたを返す
4. **view: 門の出撃地図から攻め先を選ぶ、攻め中の HUD、リザルト**（済み・`scripts/ringfall-shots-sortie.mjs`）。野営の「今日の作戦」・次の一手・やり返すは、まだ外側の取り合いを指す（⑦で付け替える）
5. **自分の陣地が攻められる。** AI が留守中に陣地を攻め、島の知らせ・やり返すへ
6. **本物のお隣**（`IslandDO` で攻めの結果を届ける）
7. **外側の取り合いと荒地の戦場を削除**し、部隊戦を陣地の攻め合いに置き換える
