# RINGFALL のモデルの決めごと

`src/ringfall/view/models.ts` が組むモデル（ロボット、リオ、銃と手、拾える物、補給箱など）を、作る前に決めた枠の中で作るための決めごと。ドット絵でキャンバスの大きさとパレットを先に固定するのと同じく、大きさ・色・最小の細かさ・予算を先に決め、`npm run models:ringfall` がそれを測る。

モデルを足すか変えたら、`npm run models:ringfall` を実行し、表とシルエットの画像を見てから出す。下の決めごとを破ると、検査は破った項目を挙げて失敗する。

## 決めごと

### 色はパレットから取る

色は `PAL`、`PROP_PAL`、`RARITY_COLOR`（どれも `models.ts`）の値だけを使う。新しい色が要るときは、名前と用途を書いて `PAL` に足してから使う。16 進の色をモデルの組み立ての中に直に書かない。

組んだモデルの材質の色がこの 3 つのどれにも無いと、検査は失敗する。

### ロボットの大きさは sim の当たり判定から決める

ロボットが撃たれて当たるかどうかは、sim の 2 つの球で決まる。胴の球（`ENEMIES[].bodyY` の高さ、半径 `radius`）と、弱点の球（`weakY` の高さ、前へ `weakFwd`、半径 `weakR`）。モデルは見た目だけで、当たりには関わらない。

見た目と当たりがずれると、見えている所を撃っても当たらず、何も無い所を撃って当たる。検査は正面と横のシルエットを 2 cm の格子に描き、次を出す。

| 項目 | 意味 |
| --- | --- |
| hit share | シルエットのうち球に入る割合。見えている所を撃って当たる割合 |
| air share | 球のうちシルエットの外の割合。何も無い所を撃って当たる割合 |
| eye in weak point | 赤い目のレンズが弱点の球の中にあるか |
| nothing hittable below | これより低い所は、見えていても当たらない |

`shots/ringfall/models/<種類>-front.png` と `-side.png` は、灰色が見た目だけ（撃っても外れる）、緑が見た目と球の重なり、赤が球だけ（空中なのに当たる）。

見た目と当たりのずれは、今の形を保つ範囲で許す。脚は当たらない部分として扱い、ずれをこれ以上広げないことだけを守る。目のレンズは、中心だけでなく全体を弱点の球の中に置く。下限の値は `scripts/ringfall-models.ts` の `ROBOT_FLOOR` にある。下限を上げるのは、モデルか sim の当たり判定を変えるときだけにする。

### 見る距離から最小の細かさを決める

横 90° の視野を幅 1920 画素で描くとき、距離 d m の 1 画素はおよそ d / 960 m になる。部品の細さ（棒なら太さ、板なら狭いほうの辺）がこれを下回る距離では、その部品は描いても見えない。細さは部品自身の面の向きごとに測るので、斜めに付けた部品も実際の太さで測れる。検査は各モデルで最も細い部品と、それが 1 画素を下回る距離を出す。

モデルごとに「主に見られる距離」が違うので、基準もそれに合わせる。

| 種類 | 主に見られる距離 | 決め方 |
| --- | --- | --- |
| ロボット | 交戦中に撃ってくる距離 | `SIGHT[].range × AWARE.engagedRange`（grunt で 56 m） |
| 手に持った銃と手 | 1 m 以内 | 一人称の視点 |
| 拾える物、補給箱、中継ボックス | 数 m〜20 m | 近づいて使う |
| 乗り物、核 | 霧の中まで | 遠くから目印になる |

形を読ませる部品（目、肩、頭、武器の輪郭）は、主に見られる距離で 2 画素以上にする。それより細い飾りは、近くで見たときの手触りのためだけに置く。

### 予算

三角形の数・メッシュの数（材質ごとにまとめた後）・材質の数（光の輪などのスプライトを含む）に、種類（ロボット、リオ、銃と手、拾える物、世界に置く物、リングの残骸のような大きな置き物）ごとの上限がある。検査は `models.ts` が公開する組み立て関数が作るものを、拾える物は全種類まで組んで測る（地図の箱から作る建物と小物は対象外）。値は `scripts/ringfall-models.ts` の `BUDGET` にあり、決めたときに測った各種類の最大値より 2〜3 割大きい。今の見た目を保ったまま、気づかないうちに費用が倍になるのを止めるための上限で、詳しく作り込む余地はその範囲に収める。上限を超える作り込みが要るときは、上限を上げる理由を doc に書いてから上げる。
