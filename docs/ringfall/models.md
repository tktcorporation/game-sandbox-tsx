# RINGFALL のモデルの決めごと

`src/ringfall/view/models.ts` が組むモデル（ロボット、リオ、銃と手、拾える物、補給箱など）を、作る前に決めた枠の中で作るための決めごと。ドット絵でキャンバスの大きさとパレットを先に固定するのと同じく、大きさ・色・最小の細かさ・予算を先に決め、`npm run models:ringfall` がそれを測る。

モデルを足すか変えたら、`npm run models:ringfall` を実行し、表とシルエットの画像を見てから出す。下の決めごとを破ると、検査は破った項目を挙げて失敗する。

## 一覧で見る

数字とシルエットだけでは、モデルが良く見えるかどうかは分からない。`npm run build` の後に `npm run models:ringfall -- --sheet` を実行すると、ゲームと同じ材質・同じ日差しと空の明かり・同じトーンマッピング・同じ視野で全モデルを描いた一覧が `shots/ringfall/models/sheet-<名前>.png` にできる（`--only robots,guns` で一部だけ）。モデルを変える前と後にこの一覧を見比べる。

| 一覧 | 中身 |
| --- | --- |
| `robots` | 各ロボットを近く（grunt で 8 m）から、正面・斜め前・横・斜め後ろ |
| `robots-range` | 各ロボットを交戦距離から。ゲームの画素を 6 倍に拡大し、砂・コンクリート・塩田・岩・アスファルトの上に置く |
| `robots-line` | 5 種を 24 m に並べたもの、プレートと陣営ごとの塗り分け |
| `ally` | リオを 5 m から 4 方向、20 m でグラントと並べたもの |
| `guns` | 一人称の描画そのまま（腰だめと覗き込み、1920×1080 の切り抜き）と、左右の真横 |
| `loot` | 拾える物を 3 m から |
| `world` | 補給箱、金庫、中継ボックス、物資、入口の目印、核の光、ボート、降下艇、リングの残骸 |

一覧のマスは、ゲームの画面（横 90°、1920×1080）からモデルの周りだけを切り抜いたもので、モデルは遊んでいるときと同じ画素数で写る。描いているのは `src/ringfall/view/modelsheet.ts` で、ページを `?models` 付きで開いたときだけ読み込まれる（ブラウザで `/ringfall/?models` を開けば同じ一覧を見られる）。

## 決めごと

### 色はパレットから取る

色は `PAL`、`PROP_PAL`、`RARITY_COLOR`（どれも `models.ts`）の値だけを使う。新しい色が要るときは、名前と用途を書いて `PAL` に足してから使う。16 進の色をモデルの組み立ての中に直に書かない。

組んだモデルの材質の色がこの 3 つのどれにも無いと、検査は失敗する。

### ロボットの大きさは sim の当たり判定から決める

ロボットが撃たれて当たるかどうかは、sim の 2 つの球で決まる。胴の球（`ENEMIES[].bodyY` の高さ、半径 `radius`）と、弱点の球（`weakY` の高さ、前へ `weakFwd`、半径 `weakR`）。モデルは見た目だけで、当たりには関わらない。

見た目と当たりがずれると、見えている所を撃っても当たらず、何も無い所を撃って当たる。検査は正面と横のシルエットを 2 cm の格子に描き、次を出す。

| 項目 | 意味 |
| --- | --- |
| hit share | シルエットのうち球に入る割合。見えている所を撃って当たる割合 |
| air share | 球のうちシルエットの外の割合。何も無い所を撃って当たる割合 |
| eye in weak point | 赤い目のレンズが弱点の球の中にあるか |
| nothing hittable below | これより低い所は、見えていても当たらない |

`shots/ringfall/models/<種類>-front.png` と `-side.png` は、灰色が見た目だけ（撃っても外れる）、緑が見た目と球の重なり、赤が球だけ（空中なのに当たる）。

見た目と当たりのずれは、今の形を保つ範囲で許す。脚は当たらない部分として扱い、ずれをこれ以上広げないことだけを守る。目のレンズは、中心だけでなく全体を弱点の球の中に置く。下限の値は `scripts/ringfall-models.ts` の `ROBOT_FLOOR` にある。下限を上げるのは、モデルか sim の当たり判定を変えるときだけにする。

### 見る距離から最小の細かさを決める

横 90° の視野を幅 1920 画素で描くとき、距離 d m の 1 画素はおよそ d / 960 m になる。部品の細さ（棒なら太さ、板なら狭いほうの辺）がこれを下回る距離では、その部品は描いても見えない。細さは部品自身の面の向きごとに測るので、斜めに付けた部品も実際の太さで測れる。円盤や貼り物のような平らな部品は、面の中での狭い方の幅で測る。検査は各モデルで最も細い部品と、それが 1 画素を下回る距離を出す。

モデルごとに「主に見られる距離」が違うので、基準もそれに合わせる。

| 種類 | 主に見られる距離 | 決め方 |
| --- | --- | --- |
| ロボット | 交戦中に撃ってくる距離 | `SIGHT[].range × AWARE.engagedRange`（grunt で 56 m） |
| 手に持った銃と手 | 1 m 以内 | 一人称の視点 |
| 拾える物、補給箱、中継ボックス | 数 m〜20 m | 近づいて使う |
| 乗り物、核 | 霧の中まで | 遠くから目印になる |

形を読ませる部品（目、肩、頭、武器の輪郭）は、主に見られる距離で 2 画素以上にする。それより細い飾りは、近くで見たときの手触りのためだけに置く。これは下の「読みやすさ」で検査する。

### 予算

三角形の数・メッシュの数（材質ごとにまとめた後）・材質の数（光の輪などのスプライトを含む）に、種類（ロボット、リオ、銃と手、拾える物、世界に置く物、リングの残骸のような大きな置き物）ごとの上限がある。検査は `models.ts` が公開する組み立て関数が作るものを、拾える物は全種類まで組んで測る（地図の箱から作る建物と小物は対象外）。値は `scripts/ringfall-models.ts` の `BUDGET` にあり、決めたときに測った各種類の最大値より 2〜3 割大きい。今の見た目を保ったまま、気づかないうちに費用が倍になるのを止めるための上限で、詳しく作り込む余地はその範囲に収める。上限を超える作り込みが要るときは、上限を上げる理由を doc に書いてから上げる。

### 読みやすさ

上の決めごとは費用と当たり判定を守るが、モデルが良く読めるかは守らない。遊ぶ人が一目で見分けなければならないこと（どの種類か、目はどこか、地面から浮き出ているか）を、次の項目で測る。下限は `scripts/ringfall-models.ts` の名前付きの定数にある。

| 項目 | 定数 | 下限 | 理由 |
| --- | --- | --: | --- |
| 形を読ませる部品の大きさ | `READ_PX`, `MUST_READ` | 2 画素 | 目・頭・肩・武器は、交戦距離でその種類と弱点の場所を伝える。`models.ts` の `reads()` で部品に名前を付け、主に見られる距離（ロボットは交戦距離、リオは 20 m）での画素数を測る。ロボットは全種で目、頭のある歩行型（grunt、heavy、titan）とリオは頭・肩・武器（リオは頭と武器）に名前が付いていなければならない |
| 種類どうしの輪郭の違い | `KINDS_APART` | 0.5 | 2 種のロボットを、遠い方の交戦距離の画素の大きさで正面と横から描き、足元と中心を揃えて重ねる。1 −（重なり ÷ 合わせた面積）がこれを下回ると、遠くで 2 種が同じ塊に見える。正面と横の小さい方を取る |
| 銃どうしの輪郭の違い | `GUNS_APART` | 0.35 | 手に持った銃は常に画面にある。握る位置を揃えて真横から描いた輪郭の違いが小さいと、持ち替えても同じ銃に見える |
| 地面からの浮き出し | `GROUND_APART` | 0.12 | ロボットとリオの色を面積で重み付けし、立ちうる地面の色（`GROUND_COLOURS`）それぞれとの OKLab 距離の平均を取る。ロボットは塗り分け（敵、精鋭、野良機、他プレイヤー、味方）ごとに測る。地面に溶ける塗りを足すと、ここで止まる |
| 目と装甲の色の差 | `EYE_APART` | 0.25 | 弱点の目が装甲に埋もれないこと。プレイヤーが撃つ相手の塗り分けごとに、目の色と装甲の色の OKLab 距離を測る |
| 色数 | `COLOURS` | ロボットと銃は 6 色まで・上位 3 色で面積の 9 割、リオは 8 色まで・8 割 | 細部を足すうちに色が散らばると、面で塗る絵が紙吹雪になる。細部は形と明暗で入れ、色は増やさない |
| 読める部品の数 | `READ_PARTS` | 種類ごと（grunt・heavy・titan は 35） | 主に見られる距離で 2 画素以上ある部品の数。遠くから見て残る細かさを表す。ボスの titan は grunt と同じ下限にする。最も大きく、最も遠くから見られるロボットが最も粗い、という状態（16 個、grunt は 37 個）を繰り返さないため |

OKLab 距離は、同じ距離なら同じくらい違って見える色の物差しで、黒と白が 1、見分けられる最小の差がおよそ 0.02。

1 m² あたりの三角形の数も表に出すが、下限は付けていない。大きいロボットほど面積が 2 乗で増えるので、同じ基準を全種に当てると titan に 9000 個の三角形が要ることになり、物差しとして使えなかった。銃ごとの部品数にも下限は付けていない。どの銃も 1 m では全部品が 2 画素以上あり、差が出ない。

今の下限を満たさないモデルは、`KNOWN` に「どこまで悪くなってよいか」と「何を直すか」を書いて通す。`KNOWN` の値より悪くなれば失敗し、下限を満たしたのに `KNOWN` に残っていても失敗する。
