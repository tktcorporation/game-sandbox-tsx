# マルチプレイ体験の一本化（設計パス）

**実装はまだしない。** この文書は、プレイヤーから見たマルチの触点を洗い、体験を一本の線にまとめる案を並べ、選んでもらうためのもの。

方針: [design-direction.md](design-direction.md)（拠点が主役・非同期の攻守・線に溶かす・新語を増やさない）。  
用語の正本: [glossary.md](glossary.md)（あれば）／画面上の表示名のみ。内部名は書かない。  
仕組みの詳細: [multiplayer.md](multiplayer.md)、[raid-loot.md](raid-loot.md)。  
体験の線: [ux-design.md](ux-design.md)。

体験の線（変えない）:

```
出撃 → 島で前線を押す → 持ち帰る → 拠点が育つ
```

マルチは別モードにしない。上の線のどこかに乗る。

## 用語（この文書で使う画面の語）

| 語 | プレイヤーにとっての意味 |
| --- | --- |
| 野営地 | レイドのあいだ帰る庭。出撃の起点 |
| 地図の机 | 島の地図を見る場所。来る遠征もここ |
| 信号所 | 他の島との窓口（送る・出撃・知らせ） |
| 工場 | 自軍のロボットを育てる場所。遠征に出す部隊の元 |
| 中継ボックス | 島の拠点で、荷物を倉庫へ送る／切り上げて帰る箱 |
| 倉庫 | 拠点に置いた物の置き場 |
| 島の守り | 留守の防衛に回る在庫。送ると自動で積まれる |

| 遠征 | 自分から他の島へ送る部隊 |
| 送る | 信号所から遠征を出す一手（非同期） |
| 出撃 | レイドを始める一手。信号所では AI の島の写しへ自分で行くこともある |
| 核 | 拠点の柱。制圧／固める |
| 制圧 | 敵や他プレイヤーの核を取って拠点を自分にする |

| 取り返す | 他プレイヤーに取られた拠点を制圧して戻す |
| 前線 | 次に取れる敵／他プレイヤーの拠点の並び |
| 島の知らせ | 誰が何をしたかの短い記録 |
| 保護中 | 新しい島など、しばらく攻められない状態 |
| AI の島 | ゲームが動かすお隣。名前の横に AI と出る |
| お隣 | 海の向こうに並ぶ他の島（本物または AI） |

## 1. いまのマルチ体験（プレイヤーが見る順）

正直に書く。機能はあるが、**一つの物語としてつながっていない**。

### 1.1 触点一覧

| # | いつ・どこ | 見える／やる | プレイヤーが理解すべきこと | 断絶・重複・説明不足 |
| --- | --- | --- | --- | --- |
| A | 野営・次の一手 | 「地図の机 · 来る遠征を固める」「{拠点}を取り返す」「工場 · 次の段を上げる」など | 今日の一手 | マルチと PvE が同じ一行に並ぶが、全体像は出ない |
| B | 地図の机 | 島・来る遠征の印・残り時間 | 「誰かが来る」 | 来る遠征と夜の襲撃が似た月印で、違いが薄い |
| C | 出撃画面 | 来る遠征の行、固めると書けること | 出る前に守りを意識 | 攻め（前線）と守り（来る遠征）が同じ画面に載り、主役がぼやける |
| D | レイド中・核（自分） | 核 · 固める → 固めた · 来る遠征をはねる／夜の襲撃をはねる | 固める＝盾 | 「固める」単体では結果が読めない初見が多い |
| E | レイド中・核（他プレイヤー／敵） | 核 · 制圧 → 倉庫へ届く（他プレイヤー時） | 取り返す／攻めると倉庫が育つ | 敵制圧と他プレイヤー制圧の差が、トーストの一文だけ |
| F | 中継ボックス | 倉庫へ送る → 「島の守りに回る」 | 送る＝留守の守り | 自動すぎて、次の一手に「守りを厚くする」が残らない |
| G | リザルト | 倉庫へ届いた／島の守り／島の知らせ／遠征の知らせ | 今日の攻守の結果 | 知らせが複数見出しに割れ、一本の物語にならない |
| H | 信号所・お隣 | カード、航路の錠、送る | 誰に送れるか | 航路・お隣・島の番号が同時に見え、入口が重い |
| I | 信号所・送る | 拠点を選んで送る | 非同期で相手島へ部隊が行く | 「送る」と「出撃」（率いる）が並び、どっちが主か不明 |
| J | 信号所・出撃（AI） | AI の島の拠点へ出撃 → 写しで制圧 → 倉庫へ届いた | 自分で相手拠点を襲う | 送る／出撃／取り返すの三系統が「攻める」を分裂させる |
| K | 信号所・島の知らせ | 取られた・全滅・仕返し | 何が起きたか／仕返しへ | リザルトの知らせと二重。読む場所が信号所に閉じがち |
| L | 工場パネル | 「島の守り n・遠征 n（信号所から）」 | 部隊が割かれている | 工場なのに信号所の話が出る。場所のプライマリが割れる |
| M | 海・地平線・地図の緑 | お隣の気配 | 「他がいる」 | 触らなくてもよい受動だが、次の一手に結びつかない |
| N | 保護中 | 出撃できない | 新規は守られている | 初見で理由が短い |
| O | AI と本物 | 名前横に AI | 偽物だと分かる | ルールは同じなのに入口が二枚（送る／出撃） |

### 1.2 プレイヤーが感じる「つながっていない」理由（要約）

1. **攻める手段が三つある** — 前線で取り返す／信号所で送る／信号所で出撃（写し）。同じ「相手の拠点を取る」のに場所も動詞も違う。
2. **守る手段が散らばる** — 地図の机で予告、レイドで固める、中継ボックスで自動の島の守り、工場で部隊を残す。一本の「守り」の物語にならない。
3. **信号所が第二のゲーム** — お隣・航路・番号・送る・出撃・知らせ・仕返しが一つの板に載り、出撃→前線→持ち帰るの線の外に見える。
4. **結果が閉じない** — リザルトと信号所と地図の机に同じ系統の文が分かれ、帰営後に「だから次はこれ」が一文で言えないことがある。
5. **用語の揺れ** — 工房／作業場／隠れ家、固める／はねる、送る／出撃、などが初見の負荷を上げる（glossary で別途整理中）。

### 1.3 削る・統合の候補（いまのまま残すと線が細いもの）

| 候補 | 扱い案 | 理由 |
| --- | --- | --- |
| 信号所の「出撃」（率いる）と「送る」の併記 | **どちらかを主、もう一方を後段か削除** | 「攻める」が分裂する最大因 |
| 島の番号の手入力 | 友達用に折りたたみ／後回し | お隣カードで足りる日常の入口を濁す |
| 工場パネルの遠征一行 | 信号所だけに寄せる | 工場のプライマリは段を上げる |
| リザルトの「遠征の知らせ」と「島の知らせ」の二重 | **一つの「島の知らせ」に統合** | 帰営の物語を一本に |
| 航路の説明を前面に出すこと | 錠は残し、文は最小 | 覚える名詞を増やさない |
| 地平線の気配＋地図の緑＋お隣カードの三重 | 気配は残し、説明はしない（現状維持可） | 受動はよいが、入口は信号所か次の一手に一本化 |
| 仕返しボタン | 残すなら「取り返す／送る」と同じ語へ | 新モードに見せない |

## 2. 再構成案（実装なし）

共通の制約:

- 線は常に **出撃 → 前線 → 持ち帰る → 拠点が育つ**。
- CoC 型: 拠点が主役、攻守は時間をずらす、助けは自動、戦利品は倉庫へ。
- 覚える場所／動詞／用語は **glossary にある既存語だけ**。新語ゼロが理想。
- リアルタイムの対人撃ち合いは主軸にしない。

### 案 A — 「守りは地図、攻めは前線、遠くは送るだけ」

**一文のループ:**  
野営で今日の守りか前線を見て出撃し、核で固めるか制圧して持ち帰り、倉庫と工場が育ち、信号所では遠くへ送るだけする。

| 項目 | 内容 |
| --- | --- |
| 最小の場所 | 地図の机、車両／門、核、中継ボックス、倉庫／工場、信号所 |
| 最小の動詞 | 出撃する、固める、制圧する、倉庫へ送る、送る、取り返す |
| 最小の語 | 来る遠征、前線、島の守り、倉庫へ届いた、島の知らせ |
| 削る／後回し | 信号所の「出撃」（率いる写し）、島の番号の日常利用、工場の遠征行、知らせの二重見出し |
| トレードオフ | 線は最も太い。自分で相手島を歩く快感は後回し。AI 島の「出撃」で得た動機を一時失う |

**短い物語**

- **初回:** 出撃して敵の前線を押し、中継ボックスで倉庫へ送る。島の守りに回ったと出るが、他プレイヤーはまだ薄い。
- **2 日目:** 地図の机に来る遠征。次の一手が「固める」。レイドで核を固め、はねた。
- **7 日目:** 紫の拠点を取り返すと倉庫へ届いた。信号所ではお隣へ送るだけ。知らせはリザルトで一度読む。

### 案 B — 「攻める入口は一つ：前線（島の内外を同じ制圧に）」

**一文のループ:**  
取り返す／襲うはすべて「前線の拠点を制圧して倉庫へ届ける」に揃え、信号所は相手の前線を開く扉に過ぎず、送るは留守の自動攻撃に落とす（または後段）。

| 項目 | 内容 |
| --- | --- |
| 最小の場所 | 地図の机、車両、核、中継ボックス、信号所（扉のみ）、倉庫／工場 |
| 最小の動詞 | 出撃する、制圧する、固める、倉庫へ送る（送るは自動 or 後段） |
| 最小の語 | 前線、来る遠征、島の守り、倉庫へ届いた、島の知らせ |
| 削る／統合 | 「送る」を前面から外すか「出撃」に統合。率いる写しは「その拠点への出撃」として前線リストに載せる |
| トレードオフ | 攻める体験は一本で強い。非同期送るの CoC 感が薄れるか、実装が重い（相手島を前線 UI に載せる） |

**短い物語**

- **初回:** いつもどおり前線へ。他島の話はまだ出ない。
- **2 日目:** 来る遠征を固め、生還。島の守りが効いたとリザルトで分かる。
- **7 日目:** 地図や次の一手に「向こうの拠点」が出る。出撃→制圧→倉庫へ届いた。送る作業は覚えなくてよい（または信号所の奥）。

### 推奨

**案 A を推奨する。**

理由（design-direction の順）:

1. **拠点が主役** — 持ち帰りと工場／倉庫が主。遠くの攻略は信号所の「送る」一条に残し、日常の線を太くする。
2. **非同期の攻守** — 来る遠征→固める／島の守り、送る→留守に効く、が CoC に近い。
3. **線に溶かす** — 率いる「出撃」を信号所に並べると、車両からの出撃と同名で衝突する。案 A は衝突を消す。
4. **新語を増やさない** — 既存語のまま、入口の数だけ減らす。
5. **簡素化優先** — 案 B は体験は美しいが、相手島を前線に載せる設計・実装コストが大きい。

案 B は、案 A で「送るだけだと攻めが弱い」と分かったあとの第二段階に回す。

## 3. 案 A を選んだときの「一本の絵」（実装前の目標像）

```
野営
  ├ 地図の机 … 今日の来る遠征（守り）
  ├ 次の一手 … 固める／取り返す／前線／工場
  └ 車両 … 出撃
       ↓
レイド … 核で固める or 制圧
       ↓
中継ボックス … 倉庫へ送る（島の守りは自動）
       ↓
リザルト … 倉庫へ届いた ＋ 島の知らせ（一つ）
       ↓
拠点が育つ … 倉庫・工場
       └ 信号所 … お隣へ送る（遠くの非同期攻め）／知らせの控え
```

プレイヤーに一度に覚えさせること（最大）:

1. 出撃して前線の核を取る  
2. 荷物は中継ボックスで倉庫へ  
3. 来る遠征は地図で見て、核で固める  
4. 遠くは信号所から送る  

これより多い入口は、案 A では出さない。

## 4. ユーザーへの未決事項（選んでほしいこと）

実装は、ここに答えが出てから。

1. **推奨案 A で進めるか、案 B か、別案か。**
2. **信号所の「出撃」（AI 島の写し）をどうするか**  
   - A1: 削除し、送るだけにする  
   - A2: 残すが「送る」の奥／二段目に隠す  
   - A3: 残し、車両の出撃と同列のまま（非推奨・現状に近い）
3. **「送る」は日常の必須か、上級の任意か。**
4. **島の知らせはリザルト優先か、信号所優先か（二重は解消する前提）。**
5. **glossary の文言案（工房→作業場など）を、この一本化と同時に採るか、後にするか。**
